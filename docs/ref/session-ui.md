# 세션 UI와 작업 정보 설계

2026-10-07. 세션 목록의 묶음 구조·제목 편집과 CLI 간 작업 정보 일관성을 함께 고친다.

## 문제와 원인

- 레일을 전체 세션 이름순으로 바꾸며 묶음 제목 편집 진입점을 없애고, 각 구성원 아래에 제목을 반복했다.
- tmux 목록은 처음 나온 pane의 cwd를 사용했다. 활성 window/pane과 다른 위치를 표시할 수 있었다.
- 브랜치/변경량은 별도 저장소 탐색 결과와 cwd 캐시를 섞었다. 생성 시 `@fsh_wt` 소속과 현재 위치가 다를 수 있고, 조회 시점도 달랐다.
- pane 헤더에는 이전 워크트리 기반 자동 이름/브랜치 경로가 남아 있었다.
- 조회 실패를 빈 정보로 바꾸거나 늦게 끝난 HTTP 요청이 새 push를 덮으면 정보가 사라지거나 되돌아갔다.

## 데이터 계약

세션 정체성(tmux 이름), 사용자 지정 뷰 제목, 현재 작업 위치, 에이전트 상태는 서로 다른 값이다.

1. 작업 위치는 **활성 window의 활성 pane**에서 읽는다. CLI 훅의 cwd나 세션 생성 시 워크트리 태그로 대체하지 않는다.
2. 서버가 그 cwd의 저장소 루트·브랜치·변경량을 `context` 스냅샷으로 함께 제공한다. REST와 workspace push가 같은 수집 함수를 사용한다. 응답 계약은 [API.md](../../API.md)에 둔다.
3. pane 작업 정보 조회/구독은 셸 UI 청크와 함께 지연 로딩해 초기 부팅 용량에 포함하지 않는다. 레일, Fleet, 모바일 세션 관리, 선택 카드/팔레트, pane 헤더가 이 스냅샷을 사용한다. 디렉터리는 마지막 경로 요소로 표시하고 전체 경로는 툴팁에 둔다. 브랜치가 없는 실제 Git 저장소는 `분리된 HEAD`로 표시한다.
4. `ready`, `nonrepo`, `unavailable`을 구분한다. 실패 시 **같은 cwd**의 마지막 성공만 보존하고 `정보 갱신 대기`를 표시한다. 새 cwd에 이전 브랜치나 변경량을 붙이지 않는다. 경계 거부 시 이전 값도 제거한다.
5. Git 조회는 cwd별로 합치고 최대 4개를 동시에 실행한다. 성공 캐시는 10초, 실패 재시도는 2초, 보관 상한은 256개다. I/O는 스레드에서 수행하며 경로 검사와 Git 루트 재검사는 `fsguard`에 위임한다.
6. 보이는 브라우저가 있을 때 tmux 감시를 기본 5초로 한다. 변경이 있을 때만 push한다. 따라서 외부 `cd`/브랜치 전환/수정은 정상 연결에서 보통 다음 감시 주기, Git 캐시 만료까지 포함하면 최대 약 15초 내 반영한다. 숨은 화면에서는 기존처럼 감시를 쉰다.
7. 새 push를 받은 뒤 완료된 이전 HTTP 목록 요청은 버린다. context가 없는 이전 서버의 목록은 기존 레일 폴백을 지원한다.

에이전트의 종류/상태는 기존 검증된 pane 또는 고유 cwd 귀속 규칙을 보존한다. Claude/Codex/agy의 이벤트 능력 차이를 작업 위치/Git 표시로 전파하지 않는다. Codex에서 같은 cwd의 여러 세션을 구별할 근거가 없으면 임의로 귀속하지 않는다.

## 묶음과 제목

묶음은 현재 뷰의 pane 트리에서 도출한다. 닫힌 묶음은 기존 v5 레이아웃의 기억을 사용한다. 새 그룹 저장소나 tmux 그룹 태그를 만들지 않는다.

- 레일/Fleet의 전체 세션 구역: 열린 묶음은 뷰 순서, 구성원은 pane 순서로 제목 아래 모은다. 닫힌 묶음도 하나의 제목 아래 모으며, 나머지 단독 세션은 이름순이다. 개입 필요 구역은 기존 waiting 목록을 유지한다.
- 헤더는 작은 제목과 세션 개수로 구성하고 굵은 세로선이나 버튼 테두리를 두지 않는다. PC의 편집 버튼은 헤더에 마우스를 올리거나 키보드로 포커스할 때, 터치 환경에서는 항상 표시한다.
- 제목은 구성원마다 반복하지 않는다. 헤더의 **편집** 버튼에서 열린/닫힌 묶음 모두 수정한다. 제목은 공백 제거 후 1~128자이며 세션 이름·브랜치와 독립적으로 저장한다.
- 묶음 헤더/닫힌 구성원을 누르면 기존 묶음을 함께 연다. 열린 구성원을 누르면 그 pane으로 이동한다. 함께 열기, 닫기와 완전 종료의 차이, 브라우저 탭별 저장, 실패 시 묶음 기억 보존을 유지한다.
- 모바일 세션 관리에서도 열린/닫힌 묶음 제목 편집과 작업 위치/브랜치를 제공한다. 목록 조회 실패는 기존 목록과 재시도 안내를 표시한다.
- 현재 화면에 열려 있음을 표시하던 창 아이콘은 레일/Fleet에서 생략한다. 상태 아이콘과 에이전트 식별은 유지한다. 메인/별도 워크트리 SVG는 현재 디렉터리·브랜치 텍스트로 대체한다. 공유 읽기/쓰기와 연결 화면 표시는 의미가 달라 유지한다.

## 검증

실제 Git 저장소의 하위 경로, 브랜치 전환, detached HEAD, 비저장소, 일시 실패/복구, 경계 거부, 같은 cwd 중복 조회를 확인한다. 활성 pane 선택, CLI별 동일 metadata, 동일 제목의 서로 다른 묶음, 닫힌 묶음 제목 저장/복원, HTTP/push 순서와 모바일 실패 안내를 회귀 테스트로 확인한다. 격리 서버의 실제 응답과 데스크톱/모바일 브라우저에서 제목 편집·묶음 복원·정보 갱신을 확인한다.

## 실제 확인 기록 (2026-10-07)

격리 config/workspace/state/tmux 소켓의 서버와 실제 Chrome에서 다음을 통과했다.

- 레일에서 묶음 제목 변경 → 구성원 이름 유지 → 닫힌 묶음 제목 변경 → 새로고침 → 제목 유지 → 두 세션 함께 재열기.
- 실제 Git 브랜치 전환/파일 수정 → 레일과 pane 헤더 동시 갱신. 이전 HTTP 응답을 의도적으로 지연한 뒤 새 push를 받아도 브랜치가 되돌아가지 않음.
- 생성 워크트리 태그가 남은 세션에서 비저장소로 `cd` → 현재 디렉터리로 변경되고 이전 브랜치는 제거됨.
- 390px 모바일 세션 관리에서 묶음 구성·현재 디렉터리/브랜치 확인과 제목 변경. 브라우저 JavaScript 오류 없음.

터치 표적의 CSS와 모바일 DOM은 확인했으며 이번 변경은 실제 손가락으로 재측정하지 않았다.
