# Files, sharing, code viewer

> `CLAUDE.md`의 영역 색인에서 갈라져 나온 문서다(2026-09-18). 이 영역을 만지기 전에 읽는다.

## Features

| Feature | Description |
|------|------|
| File viewer surface (ADR-44, 2.3) | `viewer.surface` setting (Settings → 모양): `sheet` (default) / `float` / `pane`. `sheet`/`float` are overlays mounted inside `#terminal-container` (`panels/viewer/overlay.js`) — opening/closing a file no longer resizes the pane tree, so xterm never `fit()`s and no `SIGWINCH` reaches vim/tmux/less (the problem N35's pane-leaf viewer had). The overlay's click-through background lets you keep typing in the terminal with the file open; Esc only closes it when focus is inside the card (terminal-focused Esc still reaches vim). `sheet` drags its height (`viewer.sheet.height`, 20–85%) with the shared `wireRatioResizer`; `float` drags position/size (`viewer.float.rect`, a JSON rect, clamped so it can never end up off-screen with no way back). A header button ("페인으로") escapes to the old `pane` behavior for side-by-side reading. `openFileInPane()` keeps its old meaning unchanged (used by "새 pane에 열기" and that escape button); `openFile()` is the new default entry point everything else calls, and branches on the setting. Compact (<720px) ignores the setting and always opens a fullscreen sheet with back-button close, same as the old modal viewer. All three surfaces share the same renderer (`viewer/file.js:renderFile`) — content code is one copy regardless of surface |
| Code viewer / diff (P2) | ⋯ menu → "Code Viewer", or the dock/rail **"파일" tab** (`viewer/tree.js`, `dir.show` — N35 §6 removed this as a modal in 2026-09-10, restored as a dock tab in 2026-09-22; the user confirmed reversing that call). Solves the problem of not being able to see code visually when developing remotely via CLI only. File tree (expand/collapse, address bar, jump to the active terminal's cwd, per-row "insert path into terminal") · syntax highlighting (highlight.js, 36 languages) · `git diff` rendering. Tree browsing and git status/diff are two separate dock tabs now ("파일" vs "소스컨트롤") — the tree tab carries no git UI, `scm.js` owns that. **Read-only, with no write API.** Since it's exposed over a public tunnel, it has three layers of defense: ① a fixed root (`VT_BROWSE_ROOTS`, default `~/GitHub` — opening `$HOME` would put `~/.ssh`·`~/.aws` in scope) ② `Path.resolve()` + `is_relative_to` (startswith is banned — sibling directories would pass. Since `resolve()` expands symlinks, links pointing outside the root are also caught) ③ a denylist (`.env*`·`*.pem`·`id_rsa`·`.ssh/`·`.aws/` etc., checked against every path component). The check lives in one place only: `server/fsguard.py`. **2.1.3: images render inline** (T3) — the bytes come from `GET /api/fs/raw`, which adds a type allowlist on top of the same browse boundary (png/jpeg/gif/webp/bmp/ico, and only when extension **and** magic bytes agree). **SVG, HTML and PDF are excluded** — served same-origin they are scriptable documents, i.e. XSS |
| File storage / upload (N19) | `~/.vt/files/` (id-based, 0700 dir/0600 files) — replaces the old path-based `/tmp/vt-uploads/`. Uploaded via keybar 📎 slot (mobile — stays visible even when the keybar is collapsed) or `Mod+K` → "파일 업로드"; **pasting an image into the terminal uploads it too**. Size cap `VT_MAX_UPLOAD_MB` (default 2048, i.e. 2GB) enforced streaming → 413; total cap `VT_FILES_MAX_GB` (default 5) and `VT_FILES_TTL_DAYS` (default 30) enforced by a cleanup pass on startup + every 6h — files with an active share or `pin` are excluded from cleanup. Old `/tmp/vt-uploads` contents are migrated in automatically on startup. **Dropping files from the desktop uploads them too** (R6): onto a terminal pane, they upload and the paths are pasted into that pane's session; onto the files panel (dock or pane), they upload and the list refreshes but nothing is typed — you are filing, not typing. Folders are skipped, several files go one request at a time (the endpoint takes one file), and a drop that lands anywhere else is swallowed with a hint instead of letting the browser navigate away to the file and lose the session. All of it, plus the `#file-input` triggers, runs through `frontend/js/term/upload.js` — the one implementation. The `#file-input` element is shared by all upload triggers (keybar, palette, the panel's 올리기 button) — never add a second one. **API is id-only** (`server/file_store.py`) — `GET /api/files/{id}/download` (`attachment`+`nosniff`+`no-store`), `DELETE /api/files/{id}`, `POST /api/files/{id}/insert` (types the path into a tmux pane, no Enter). There is no path-based download API anymore |
| Dock attachment tab (N19~N21) | dock tab **"첨부"** (also the left rail's paperclip icon and `Mod+K` → "첨부 · 공유 링크" — renamed from "파일" on 2026-09-22 when the directory tree tab took that name back). Rows carry the five actions from `50-files-share.md` §4: download / copy path / insert into terminal / issue link / delete, plus size, upload date+time (`created`, `MM-DD HH:mm` — year prefixed if it isn't this year, full timestamp in `title`) and remaining-TTL text. Chips filter `all|shared|expiring` (expiring = within 3 days) and the footer draws a quota gauge from `GET /api/files`'s `quota`. Issuing a share link is the **first UI path that requires elevation** (`require_elevated`) — a 401 prompts for the password once and retries. **A share token is never returned by the list API** (the list needs no elevation, so a token there would be a way around the elevation gate) — the [복사] button therefore only works for links issued in this browser session. No QR: the frontend carries no QR generator and the dependency isn't worth it (`fsh mobile` already makes QR codes server-side). The renderer lives in the lazy `panels` chunk — importing it into app.js pushed the bundle over its 300KiB cap. **Upload progress** (2026-09-22): `term/upload.js` uploads via `XMLHttpRequest` (not `fetch` — only `xhr.upload` gives upload-direction progress events) and broadcasts `document` `CustomEvent('vt:upload-progress')` at start/progress/done/error, keyed by a per-call `clientId`. `files.js` can't statically import that module (ADR-26 — it's core/store.js vs. the lazy `panels` chunk), so it listens for the same global event instead, the same bridge idiom as `vt:session-switch`/`vt:panel-open`. Progress rows only render while a 첨부 panel instance is open; if none is open the event is just dropped (the completion/failure toast still fires, so nothing is silently lost) |
| Share links (N21) | `POST /api/files/{id}/share` (elevated) issues a `v1.<exp>.<fileId>.<shareId>.<hmac>` token signed with the same key as session cookies (`auth.sign_payload`) — `GET /s/{token}` is the public entry point, deliberately outside `TokenAuthMiddleware`'s usual gate (`server/routes/share.py` does its own verification). **`device` mode**: requires a registered `vt_device` + valid `vt_session`; missing either → 302 to `/?next=/s/{token}` (login gate redirects back after auth, `frontend/js/gate.js`). **`pin` mode**: static PIN page (no app chrome) → correct PIN sets a 60s one-time download cookie; 5 failed attempts cancels the share. Cancelling (`DELETE .../share/{shareId}`) removes the record from `files.json` — the URL 404s immediately even though the signature is still cryptographically valid. `once` shares self-delete after the first successful download. There is no issuance dialog UI yet (dock file tab §4 — deferred, tracked with N19/N22/N23/multihost/scrollback in the 2.1.2 backlog) |
