# Worktrees and git

## Features

| Feature | Description |
|------|------|
| Dock source control | dock → "Source control". Stage/unstage/commit are wired to `POST /api/git/{stage,unstage,commit}`, and each file row gets an eye button (shown on hover) that opens the file as a pane leaf; section heads Staged (스테이지됨)/Changes (변경사항) have unstage-all/stage-all (the same endpoints with every file of the section). The commit box sits above the lists (⌘/Ctrl+Enter commits). The branch dropdown in Commit history (커밋 기록) only chooses whose history to show — no checkout. In a file's diff, clicking a line opens an instruction box whose Target (대상) picks the target session (blank = the voice auto-target rule) and adds it to the prompt queue. **push and PR/MR are deliberately absent — not disabled buttons, not rendered at all.** FarShell runs your own Mac terminal, where you already push, and anyone juggling several accounts has already solved identity with per-repo git config (SSH `Host` aliases, `git config user.email`); there is no reason for FarShell to decide "which account" for you. Committing therefore runs under **ambient git credentials**. Server-side guards are the fsguard repo resolution, a repo-relative path check on every file, a commit-message length cap, and a 400 when nothing is staged |
| Git account store (built but unused) | `~/.vt/git-accounts.json` + `~/.vt/git-bindings.json` (0600 + flock) plus a 15-minute **elevated session** (`POST /api/auth/elevate` re-verifies password + OTP and reissues the cookie with an `elev` claim; session-scoped, not device-scoped, so every tab and device elevates on its own). The write routes sit behind one `elevated_router` (`APIRouter(dependencies=[Depends(require_elevated)])`) rather than per-handler checks; reads stay on the plain router, so a write path can't be added without the guard. PATs only — no OAuth, since taking a callback on a public tunnel is the more dangerous design. Tokens are never returned, only `auth.masked`, and `fsh git-account add` takes `--token-stdin` only (never argv). **This entire layer is currently wired to nothing**: it is harmless on its own and may be reused for cross-account worktree automation. `fsh git-account` is the only way to reach it; no UI does |

## Worktrees

Left rail, or `fsh worktree` (which talks to `server/worktree.py` directly and works with no server running). Discovery walks the fsguard roots to depth 3, stops at the first `.git`, then reads `git worktree list --porcelain` per repo, annotating each entry with ahead/behind and change counts (one `git status --branch` plus a numstat — the same definition as the session list's location: changed files include untracked ones), the tmux sessions belonging to it, its port band and its `origin` remote — 75-second cache, every path re-validated through fsguard. Claude Code's worktrees under `<repo>/.claude/worktrees/<name>` are listed: fsguard lets Git-metadata callers (`resolve_under_roots(..., git_meta=True)`) through that one `.claude` component only when `<repo>/.git` is a directory and the tree's `.git` file points into `<repo>/.git/worktrees/`; browsing, search and every other `.claude` path stay denied. A session belongs to a worktree by its `@fsh_wt` tag; an untagged session is assigned by its **active** pane's cwd to the **deepest** worktree containing it (a tree nested in the main checkout wins over the main checkout) and tagged then. Tagged and untagged sessions of the same tree are both listed.

**Every write route wraps `worktree.py` in `asyncio.to_thread`.** `create_worktree`/`open_worktree`/`delete_worktree` are synchronous — `create` runs `git worktree add` plus, in copy mode, a blocking `shutil.copytree`; `open`/`delete` call `find_by_id(force=True)`, which ignores the cache and re-runs full discovery (measured at 1.0–1.7s). Calling them directly on the event loop would freeze the whole server (HTTP, WebSocket, every session's PTY output) for as long as the git call takes. `GET /api/worktrees` follows the same rule, and `test_no_blocking_in_async.py`'s `BLOCKING` list names all three write functions alongside `list_worktrees`.

**Session ownership is a tmux fact, not a server guess ** Each tmux session that `_open_agent`/`open_worktree` create gets a custom option, `@fsh_wt <worktree id>`, set with `tmux set-option`. `_sessions_for_path` reads that tag first (one extra `\t#{@fsh_wt}` field on the batched `list-panes -a` call already used for discovery — no new subprocess). Only when no session carries the tag does it fall back to a cwd-containment check, and a fallback hit self-heals by writing the tag on the spot, so the next scan reads the tag directly. This exists because `server/session_store.py` is memory-only and dies with the server on restart while the tmux session (and its cwd) survives — storing the association there would have silently reset every restart. `POST /api/tmux/create` also accepts an optional `worktreeId` (validated as a 12-hex `sha1[:12]`) to tag sessions it creates; the current frontend does not send it.

**Depth is per root, not global.** A container-shaped directory name (`GitHub`, `projects`, `src`, `repos`, `work`, …) grants one extra level below it, so `~/GitHub/work/proj` is found even when the boundary is `$HOME`; everything else stays at depth 3. Raising the depth everywhere would walk `~/Library` and `~/.cache`, so the scan also skips a **scan-only** exclusion list (`worktree.SCAN_EXCLUDE_DIRS`: `Library`, `Downloads`, `Applications`, `go`, `.cargo`, …). That list is deliberately *not* `fsguard.EXCLUDE_DIRS` — the file browser shares that set, and hiding `~/Downloads` from the scan must not make it unbrowsable. The scan stops at 200 repos and reports `truncated: true`.

The `origin` remote (`remote: {host, owner, name}`) is read straight from `.git/config`, never via `git remote get-url` — one file read instead of one subprocess per repo. Credentials embedded in the URL (`https://user:token@host/…`) are stripped by the parser and fixed by a test. The `remote` is returned by `/api/worktrees` and `/api/repos`.

**Hiding repos from the rail.** `~/.vt/repos.json` (0600 + flock, managed by `repo_store.py`) holds hidden-repo records keyed by `sha1(host+path)`; `GET /api/worktrees` filters them out, `?include_hidden=1` returns them flagged for the settings sheet, and `POST /api/worktrees/hidden` toggles one. It lives on the server, not in device settings, because "is this my project?" is a judgement that should hold on every device — unlike rail group collapse, which is per device. Hiding a repo also hides its linked worktrees, and a path that no longer exists is ignored rather than cleaned up.

**Deleting a worktree.** On the repository management sheet (`RepoVisibility.tsx`), a non-main worktree row has a "삭제" button that calls `DELETE /api/worktrees/{id}`. The confirm flow is two-step: a plain confirm first (mentioning that any open session's tmux stays alive but won't auto-reconnect), then — only if the server refuses with 409 `dirty:true` — a second confirm naming the uncommitted changes before retrying with `force:true`. The main worktree never gets this menu item (the server also refuses it with 400).

Creation is fixed at `~/.worktrees/<repo>/<name>` on branch `feat/<name>` and does four optional steps: node_modules (**symlink by default**, so a new worktree is usable without a reinstall), `.env` (`inherit` — only *existing* `PORT`/`VITE_PORT`/`DEV_PORT`/`NEXT_PUBLIC_PORT` lines are rewritten to the assigned band; missing keys are never added, and `.env` content is never returned by the API), a port band (5200, +100 per worktree, recorded in `~/.vt/worktrees.json` 0600 + flock), and an agent launched in a detached tmux session named `wt-<repo>-<branch>`.

**Every step after `git worktree add` rolls back on failure** (node_modules removed, then `git worktree remove --force` + `git branch -D`) so a half-built worktree never survives.

Delete refuses the main worktree outright and returns 409 `dirty:true` on any uncommitted change unless `force:true`; tmux sessions are only killed with `killSessions:true`, and the branch is never deleted.

Because a symlinked node_modules reflects the main repo's *current* tree rather than `base`, `GET /api/worktrees/precheck` hashes package.json + lockfile on both sides and raises a `lockfile_mismatch` warning before the create dialog.

`~/.worktrees` is auto-added to the fsguard roots when it exists — without that, every worktree created here would sit outside the browse boundary and be silently dropped from its own list

## Agent turn checkpoints (core; nothing calls it yet)

`server/checkpoints.py` can record a work folder's state as a git commit under a hidden ref, so a later step can show what an agent turn changed. **This step ships the core only: no hook, route or UI calls it, so nothing runs automatically.** It is switched on per repository by a later step; read this section before wiring it.

- **Where it lives.** Objects go to the user's own `.git/objects`; refs to `refs/fsh/ckpt/v1/<wt12>/<session>/<seq:06d>` (safety copies before a restore: `…/<wt12>/restore/<UTC seconds>`). `wt12` = `sha1(real path of the absolute git dir)[:12]`, so linked worktrees, which share `refs/`, stay apart. Refs are the only durable store; FarShell's state folder holds nothing. Metadata (kind, turn, agent, trusted, skipped count) is in commit-message trailers `FarShell-…`; paths, prompts and tmux names are never written there.
- **What it never changes.** The user's branch, HEAD, index bytes and working tree are only read. The snapshot is built in a temporary index (`<git-dir>/fsh-ckpt-index-<uuid>`, a copy of the user's index so the stat cache is reused; a split index starts from `read-tree HEAD`), removed afterwards. FarShell never runs `git gc`/`prune`; objects of deleted refs wait for the user's own gc.
- **What it leaves out.** Names `fsguard.repo_relpath_denied` refuses (`.env*`, `*.pem`, `id_rsa`, `.ssh/`, dot folders outside `ALLOWED_DOT_DIRS`), untracked files over `VT_CKPT_MAX_FILE_MB` (default 2 — a measurement showed big untracked files were most of the cost), untracked nested repositories, and everything `.gitignore` excludes. More than `VT_CKPT_MAX_PATHS` (5000) paths or `VT_CKPT_MAX_BYTES_MB` (100) changed bytes gives `too_large` and no ref. Sparse checkouts are `unsupported`; a merge/rebase/cherry-pick in progress is `skipped_busy`. An identical state (same tree and HEAD as the session's last checkpoint) makes no ref (`unchanged`).
- **Safety.** Every git call uses `git_safe.argv` (no hooks, no fsmonitor) and `resilience.proc.run` with a 30 s deadline (`VT_CKPT_TIMEOUT`) that kills the process group; the whole capture holds a per-git-dir `TimedLock` (3 s wait → `busy`). Commits use a fixed identity and `commit.gpgSign=false`, so a missing `user.name` or forced signing cannot fail or stall it. Not covered: a repository whose own `.git/config` is attacker-written can still define `filter.<x>.clean`, which `add` runs (same category as the `git_safe` note above).
- **Residual exposure (not hidden).** A secret under a name the deny rules do not know (an untracked, non-ignored `my-secret.txt`) enters `.git/objects`; `git push --mirror` would push `refs/fsh/*`; `git log --all` and some graph tools show «FarShell checkpoint» commits. That is why a later step makes it opt-in per repository.
- **Reading.** `list_refs`, `turn_files` (`--numstat`; base = the same turn's trusted `pre-turn`, else the earlier `turn-end`/`baseline`, else the parent HEAD; `head_moved` when the two parents differ — a heuristic, not a verdict on pulled files), `diff` (through `routes.git._redact_diff`, 1 MB cap, `file` rejected if absolute, `..`, `-…` or contains NUL).
- **Cleanup.** `gc` removes, per work folder only: turn checkpoints beyond `VT_CKPT_KEEP_TURNS` (30, the baseline is kept), sessions idle over `VT_CKPT_KEEP_DAYS` (14), safety copies over `VT_CKPT_KEEP_RESTORE_DAYS` (7), then the oldest beyond `VT_CKPT_MAX_REFS` (500). Manual removal: `git for-each-ref --format='delete %(refname)' refs/fsh/ | git update-ref --stdin`.
- **Measured (this Mac, Apple Git 2.54, 20 captures each).** FarShell-sized repo p95 0.22 s, 30,000 tracked files p95 0.17 s, ~13 KB of objects per capture; a repo with 40 MB of untracked data re-hashed it on every capture (0.2 s) and grew `.git` by 40 MB on the first. Tests: `test_checkpoints_capture.py`, `test_checkpoints_gc.py`.

## Session workspace display

**Every server git call goes through `server/git_safe.py`.** A pane cwd or a picked repo can be an attacker's repository, and git reads that repository's config: `core.fsmonitor` runs a program on `status`, and a bare-repository-shaped folder committed inside a normal repo is *discovered* as the repository once you `cd` into it, so its config is attacker-written even after a plain `git clone`. The rail badge runs `git status` for the pane cwd unprompted, so without these flags it would be a no-click command execution. `git_safe.argv` adds `-c safe.bareRepository=explicit -c core.fsmonitor=false` everywhere and `-c core.hooksPath=/dev/null` unless the call carries out a git action the user asked for (dock commit, worktree add/remove keep the repository's hooks, as the CLI would; `authz/lease_cli.py` also keeps it because `rev-parse --git-path hooks` must see the real value); `git_safe.env` sets `GIT_OPTIONAL_LOCKS=0`/`GIT_TERMINAL_PROMPT=0`; diff/show add `--no-ext-diff --no-textconv`. Consequences: a folder that *is* a bare repository shows as unavailable; textconv drivers do not apply in the dock diff. Not covered: a repository whose own `.git/config` the attacker wrote (unpacked archive, an agent allowed to write it) can still name a `filter.<x>.clean` that `status` runs — git has no generic switch for filters. `updater.py` (FarShell's own checkout) is left as is. `worktree create` refuses a `base` that starts with `-` or holds control characters (it would reach `git show {base}:…` and `git worktree add` as an option). Tests: `server/tests/test_git_safe.py` (plants the bare repo and checks the marker file).

**Diff redaction reads every header git can write.** `_redact_diff` hides the hunks of any file the viewer would refuse. git C-quotes non-ASCII, `"`, backslash and control characters (`diff --git "a/\354\204\234.pem" ...`), and merge conflicts and merge commits use `diff --cc` / `diff --combined`, so parsing only `diff --git a/X b/Y` would leak the body and merge it into the previous (allowed) section. Every `diff --git|--cc|--combined` line starts a section; quotes are decoded; an ambiguous unquoted `a/X b/Y` (spaces) is split at every ` b/` and **any** candidate, plus `rename from/to` and `---`/`+++` lines, being denied hides the section; a header that cannot be read hides it too (fail closed). `_diff_path_denied` also applies the viewer's hidden-directory rule (`.sometool/state.json`; allow set and dotfiles unchanged). Diff and show use `core.quotePath=false` (`git_safe.argv(readable_paths=True)`) so Korean names stay readable. Tests: `test_git_diff_redaction.py`.

Session cards describe the active pane’s current location, independently of creation ownership (`@fsh_wt`). They distinguish the primary workspace (`메인`) and linked worktrees (`WT`) through Git directory/common-directory resolution, including trees made by Codex, Claude or plain Git outside FarShell.
