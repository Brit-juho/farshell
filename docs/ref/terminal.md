# Terminal, panes, shell surface

> `CLAUDE.md`의 영역 색인에서 갈라져 나온 문서다(2026-09-18). 이 영역을 만지기 전에 읽는다.

## Features

| Feature | Description |
|------|------|
| Clipboard sync | OSC52 (in-terminal copies) + `fsh clip` polling daemon (copies outside the terminal) → pushed to web clipboard |
| Paste (N24·N25·N26·N29, 2.1.5) | **The server decides, not the browser.** The browser cannot know whether the app inside a pane turned bracketed paste on, so guessing meant `200~` printed literally in the wrong place, or auto-indent stair-stepping in the right one. The server now reads the pane's real input mode — `ICANON` via termios, DECSET 2004 seen on the output stream — and decides. Path: WS `paste` message, or `POST /api/sessions/{id}/paste`. **tmux sessions are delegated to tmux itself** (`paste-buffer -p` looks at the pane's actual mode; `-S` on 3.7+ also turns off tmux's own sanitising since we already did it) — we do not guess a second time. Control characters are whitelisted by iTerm2's rule (tab · LF · FF · CR · `^V`); ESC is neutralised to `␛` only when bracketing, and simply dropped otherwise. In canonical mode a line over `PC_MAX_CANON` (1024B on macOS) does **not** get truncated — the whole line vanishes (verified on a real PTY) — so it is now refused up front with a reason instead of disappearing. `fsh doctor paste` shows what this terminal actually sends |
| tmux session management | Create/attach/detach/kill tmux sessions from the web |
| Scrollback buffer | Restores previous output on WS reconnect (up to 5000 chunks) |
| Scrollback persistence (N13) | Opt-in, default OFF — `scrollback.persist` setting toggle (Settings → 스크롤백). ON appends PTY **output only** (never input — the hook point is `pty_manager._flush_session`, not `write()`) to `~/.vt/scrollback/<session>.log` (0600), rotating at 20MB (one `.1` generation kept), 7-day retention via a periodic cleanup pass. The client still only ever receives the most recent 256KB on reconnect regardless of this setting — persisted history is read separately via `GET /api/sessions/{id}/scrollback?before=` ("load more", base64-encoded, paginated newest→oldest). `server/scrollback_persist.py`. Since 2.1.2 the palette's `~` search reads these logs too — one source per session (log if present, else the live ring, never both), so output from a finished session or from before a server restart is searchable; a log is scanned from its tail up to 4MB. |
| Terminal search | Ctrl+F / Cmd+F → xterm.js search addon |
| Session name editing | The ✎ on a rail session row, or the mobile session sheet → rename (PATCH API; the tmux session name is also changed via `rename-session` — if the new name isn't alphanumeric/dash/underscore, tmux is left untouched and only the web label changes). 2.1.4 removed the session tab strip, so there is no "double-click the tab" path — the single source of a session's name is its record (`sessionDisplayName` in `core/store.js`) |
| Split panes (2.0) | The terminal area is a binary tree of panes. Split from the pane header or by dropping a **rail session row** on a pane edge (5 drop zones; before 2.1.4 the drag source was the session tab); the divider is draggable. Pane cap per width tier (compact 2 / regular 4 / wide 6) — over the cap the split buttons are disabled with the reason in their tooltip, rather than silently doing nothing. On <720px touch devices the same tree renders one pane at a time with left/right swipe between them. The layout is saved to `/api/workspace` and restored on load; a leaf whose session died is demoted to an empty pane instead of a ghost |
| Left rail + command palette (2.0) | The ⋯ menu is gone. The left rail (sessions / files / queue / ports / usage / settings) is the pointer path and `Mod+K` the keyboard path — **both expose the same things**, so learning either one is enough. The palette shows each command's current key binding, read from the keymap registry |
| Settings + keymap (2.0) | `Mod+,`. Settings live in `/api/workspace.settings`, so a change on your phone shows up on the Mac. Key bindings are rebindable, and **`passthrough` hands a key back to the terminal** — that's how you get `Mod+F` back as the shell's `forward-char`. Mouse section can turn off "forward mouse events to the app", making drag-select always work even under vim/tmux mouse mode. **Defaults differ per platform** — see the row below |
| Platform key defaults (2026-09-18) | `Mod` is Cmd on macOS but **Ctrl everywhere else**, so the mac-safe defaults were taking keys the shell and tmux actually use. `keymap.js` now carries a `defNonMac` per action: `search` Ctrl+Shift+F, `palette` Ctrl+Shift+K, `splitRight` Ctrl+Shift+D, `searchInPane` Alt+Shift+F, `splitDown` Alt+Shift+D, `paneClose` Alt+Shift+W, `railToggle` Alt+Shift+B, `worktreeNew` Alt+Shift+N. **`paneClose` and `worktreeNew` moved on macOS too** (Ctrl+Shift+W / Ctrl+Shift+N): their old Cmd+Shift+W / Cmd+Shift+N are the browser's close-window and incognito, so they never reached us in a normal tab. Rule: prefer `Ctrl+Shift+…` (a terminal cannot encode it), drop to `Alt+Shift+…` when that slot is taken or the browser owns it (Ctrl+Shift+W closes the window, Ctrl+Shift+N opens incognito, Ctrl+Shift+B toggles the bookmarks bar); the reserved list now also carries the Shift variants and is compared **normalized**, so a combo recorded in the settings screen ('mod+shift+w') is caught too. `Ctrl+Alt` is avoided because it is AltGr on European layouts. `Mod+…` elsewhere in these docs means the macOS default. A user's own rebinding always wins and stays platform-independent |
| Connected screens (2.0) | rail → Sessions → "Connected screens". Lists every client attached to that tmux session with a "me" badge, and "Keep only this screen" detaches the rest (including a Mac iTerm2 window). You never send a tty — the server derives yours from your web session id, and refuses to detach you |
| Session cards (pane-picker, palette) | The "pick a session" sheet you get from clicking an empty pane, and the command palette's session rows, both reuse the same card builder (`agent/preview.js`). Through 2.1's step 4 each card opened its own `/ws-preview` WebSocket per session to stream a live, ANSI-rendered terminal snippet — with the palette, pane-picker and the (CSS-hidden but still-loaded) legacy rail all doing this at once, one session could have three such sockets open. **2.1 D5 removed the live preview**: the card's meta line is now a static `cwd` string filled from the same `/api/tmux/sessions` response the card already needed for its title/command, no socket required. The `/ws-preview` **server endpoint itself is untouched** (ADR-7) — only the frontend stopped opening it |

ADR-20's own blocking argument for that model (rail rows shifting under `cd`) was resolved by D2's `@fsh_wt` tagging, which is what made the reversal possible. Awake sessions render in `buildSessionSections()` (`shell/rail-data.ts`): an "개입 필요" bucket for waiting/error regardless of group, then group buckets (group order from `group_store`, unlabeled auto-suggested groups fall back to the session's `@fsh_wt`→repo name via `groupDisplayLabel()`), then "묶지 않음" for sessions with no group and no repo. Asleep sessions never enter those buckets — `buildSleepingEntries()` puts them in a separate "잠자는 중" zone, collapsed by default: a group that slept as a whole renders as one cluster row (click wakes every member via `Promise.all(attachTmux)`), a session that slept alone renders as a solo row (click wakes just it). The session context menu gained "완전 종료" (`vtConfirmAndKillSession`), previously reachable only from the `tmux-panel.js` popup, and "깨우기" for asleep rows. Remote hosts are untouched (2.2 range) — they keep the old 3-bucket 개입 필요/작업 중/열려 있지 않음 view via the pre-existing `buildRailSections()`, now branched on `isRemoteHost()` alongside the new local-only functions. **Step C** moved worktree management out of the rail (it lost its worktree rows in B) into the former "저장소 표시" sheet, now "저장소 관리" (`RepoVisibility.tsx`), reading `/api/repos` (grouped by repo, built in A, unused until now) instead of the flat `/api/worktrees`: repo row (unchanged show/hide checkbox + a new expand arrow, screen-only state, not persisted) → expands to that repo's worktree cards (branch, "+ 새 세션" calling the existing `openWorktree()`+`attachTmux`, "삭제" via the existing `deleteWorktreeRow()` when not main) → each card lists its tmux sessions as chips (click opens/wakes, same two-branch logic as the rail's `openRow`). The rail footer button changed from "워크트리 만들기" to "새 세션", now calling the existing global `session.add-menu` action (`#add-btn`) instead of opening a worktree dialog. The `worktreeNew` keymap (Alt+Shift+N) now opens this sheet instead of jumping straight to the create-worktree dialog. **Step D** fixed a regression B had introduced and finished the tab-identity move: B's rail `openRow` never called anything to switch tabs before `switchTo`/`attachTmux`, and those always place a session in **whatever tab is currently active** (`addSession`'s last line) — so opening a session belonging to a different repo silently overwrote the pane you were looking at instead of switching to (or creating) that repo's tab. Fixed by having the rail (and the repo sheet) call `window.openGroupTab()` (renamed from `openWorktreeTab`) before `switchTo`/`attachTmux`, for any row with a non-null `groupId` (a `⌘`-click split, or a row with no group, skips this — same as before D4). While touching that path, tab identity went from D4's `repoId` to **`groupId`** (`layout/store.js`, `layout/tabbar.js`'s `sessionBelongsToTab`/`setGroupSessionMap`, `term/tab-worktree.js`'s `effectiveGroupMap` — `@fsh_grp` first, repo id fallback, matching the rail's own groupId computation exactly) — cosmetic today since no UI can set a custom `@fsh_grp` yet (that's E), but the persisted schema is ready for it. Layout snapshot bumped to **v4** (`groupId` on each tab); v3's `repoId` is still written alongside for rollback (same value until E) and still read (promoted to `groupId` on load). The tab **×** changed from "remove from layout only" to **재우기(sleep)**: `term/session-actions.js`'s `sleepTab()` walks the tab's pane tree, detaches (sleeps) every session leaf found, then closes the tab — because a tab is now a group, closing it is closing the whole group, and a session with no tab and no other reference was already an inconsistent "awake but nowhere" state before this fix. `removeFromLayout` (layout-only, no detach) was removed since it had exactly one caller and that caller now needs the sleep behavior; "세션 놓기" (the single-session detach label, `vtDetachSession`) was renamed to "재우기" too, in the rail context menu and the mobile session sheet (`picker.js`) — same word, same underlying `detachSession`, now used at both a single-session and whole-tab granularity. Verified with a real isolated server + browser: opening sessions from two different repos correctly creates two separate tabs (previously the second silently ate the first's pane), the tab's 재우기 button sleeps every session in it while leaving tmux alive (confirmed via `attached: 0` in `/api/tmux/sessions`) and the rail immediately shows it under "잠자는 중", and waking it from there reopens it into its own tab again. **Step E** (the last one) added drag-to-regroup and finished the two cleanups the whole rollout was blocked on. Dragging a session row onto a group header calls `POST /api/tmux/{name}/group` (built in A, unused until now) to set `@fsh_grp`; dropping on "묶지 않음" clears it; "개입 필요" and "잠자는 중" are not drop targets (the former is a filtered view, not a real group; regrouping only makes sense while awake). | kitty keyboard protocol (N12) | Sends combinations that legacy encodings have no room for — `Ctrl+Shift+<letter>`, `Shift+Enter`, `Ctrl+Enter`, `Ctrl+Tab` — as CSI u (`frontend/js/term/kitty-keys.js`). Encoding happens **only while an app has turned the mode on** (`CSI > flags u`); otherwise a shell that never enabled it would literally print `\x1b[97;6u`. The mode is a push/pop stack, so a vim that opens and closes inside a shell restores the previous value. Our own UI shortcuts are matched first, so `Mod+K` never leaks to the PTY even with the mode on. ⚠ **Layer 3 (tmux `extended-keys`) is deliberately absent** — that is a change to the user's tmux server options and needs its own approval. With tmux 3.3+ and that option off, tmux blocks CSI u before it reaches the inner app (`set -s extended-keys on`) |
| Skins + theme import (N14) | Settings → "모양" (Mod+, or rail ⚙ → Settings) is the **only** place to switch skins now — `#theme-row`'s 6 chips (farshell/macos/catppuccin/windows/vscode/notepad, `theme.js`'s `vtSkins()`) render there. Same screen also lets you paste a Ghostty config or Warp theme YAML to add a 7th skin (`imported`) — the terminal palette **and inferred UI tokens**. The format is detected from the content. Arbitrary theme files really do contain things like "white background, yellow foreground", so contrast is auto-corrected until body text hits 4.5:1, status colors 3:1 and filled-button text 4.5:1; anything still short is named on screen rather than blocked (it's the user's theme). The parser and inference (`theme-import.js`) are a lazy chunk; the boot path only writes a stored token map into CSS variables (`theme-custom.js` plus an inline block in index.html — the colors must land before first paint or the theme flashes). With nothing imported, the skin doesn't exist in the list or the chips. The command palette (Mod+K → "테마") also lists all skins, reading `vtSkins()` directly rather than scanning the DOM — so it works even when the Settings panel isn't open |

### tmux-centric session management

The web UI uses tmux sessions as its default:
- On startup, tmux sessions are auto-detected → attaches to the first one
- "+ New" → creates a tmux session (`POST /api/tmux/create`)
- Closing a tab → only detaches (the tmux session stays alive). Kill is done via `DELETE /api/tmux/kill/{name}`.
  Three UI surfaces (worktree tab bar, rail context menu, mobile session sheet, tmux panel) used to each spell
  "close" their own way with their own logic. 2.1 D3 named the three real actions — **배치에서 빼기** (remove from
  layout only), **세션 놓기** (detach the web session, tmux keeps running) and **완전 종료** (kill tmux, irreversible)
  — and moved the implementations into `frontend/js/term/session-actions.js`, which the four surfaces now call
  instead of each rolling their own. The kill confirmation text names the session's agent status when it's
  `waiting`/`working`, so a session mid-approval isn't killed by mistake
- Duplicate-attach prevention: a tmux session already open in the web switches to its existing tab
- iTerm2 and the web can be attached to the same tmux session at the same time
