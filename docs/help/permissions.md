# fsh help permissions — 에이전트 승인함과 권한

에이전트가 이 맥에서 무언가를 하려면 사람의 승인이 필요한 경우가 있다 — 공유 세션을 읽고 쓰기, 다른 세션의 에이전트에게 메시지 보내기,
다른 맥에 제어 권한 주기, 에이전트가 직접 요청한 임의의 권한. 이 모든 요청이 **하나의 승인함**에 모이고, 승인한 권한은 **설정 > 권한**에서 관리한다.
승인과 회수는 비밀번호로 로그인한 브라우저(웹/폰)에서만 된다. 터미널의 `fsh authz` 는 보기 전용이다.

## 승인 요청이 오면

- 요청이 오면 결정 창이 뜬다. 한 번에 **요청 하나**만 보이고 오래된 것부터 나온다(`1 / N`). 「모두 허용」은 없다.
- 창에는 요청한 세션(위임된 하위 세션이면 계보), 대상, 요청한 권한을 **프리셋 이름**(보기 · 협업 · 운전 · 제어)으로 말한 문장,
  그리고 정확한 scope와 조건이 그대로 나온다. 에이전트가 적은 사유가 있으면 따로 표시한다.
- 선택지는 **거부 / 한 번만 / 이 세션 동안**이다. 메시지·다른 맥 요청은 한 번만을 고를 수 없고 그 이유가 창에 적힌다.
- 오조작 방지: 기본 포커스는 「거부」, 창이 뜬 뒤 잠깐은 어떤 버튼도 눌리지 않는다, Esc·배경·X는 결정이 아니라 「나중에」다.
- **높은 권한**(raw 입력, 브라우저 JS 등)이 들어 있는 요청은 눈에 띄게 따로 표시되고, 허용하려면 비밀번호를 다시 확인해야 한다.
- 알림 문구에는 세션 이름이나 요청 내용이 들어가지 않는다.
- 「나중에」로 닫은 요청은 남아 있다. 설정 버튼의 숫자 배지(대기 건수)나 설정 > 권한 > 승인 대기에서 다시 연다.

## 설정 > 권한

| 구역 | 내용 |
|---|---|
| 승인 대기 | 모든 종류의 대기 요청 한 목록. 「결정하기」로 해당 요청의 결정 창을 연다 |
| 허용된 권한 | 주체·리소스·종류로 거르는 목록. 행마다 프리셋(또는 scope 개수), 정확한 scope·조건, 누가 어떤 경로로 승인했는지, 만료·남은 횟수, 위임 계보. 「회수」는 확인을 거친다 |
| 기본 규칙 | 코드가 정한 기본 권한. 읽기 전용이라 회수할 수 없다 |
| 감사 기록 | 최근 순. 주체·리소스·기간으로 거르고, 거부 기록 포함 여부를 고른다. 해시 체인이 정상이면 중립적인 「무결성 확인됨」, 끊겼으면 경고로 보인다. 내용(입력·화면·메시지)은 기록하지도 보이지도 않는다 |
| 비상 정지 | 사람이 아닌 주체의 모든 권한을 한꺼번에 회수하고 대기 요청을 비운다. 두 단계 확인 + 비밀번호 재확인. 사람의 로그인과 기본 권한은 그대로다 |

공유 세션 권한은 「입력만 회수」로 읽기는 남기고 쓰기만 거둘 수도 있다.

## 큐에서 막힌 항목

권한이 회수되었거나 위임이 닫혀 큐 항목이 막히면 큐 패널에 사람이 읽는 이유가 나온다(코드는 그대로 API에 있다).

## 폴더 lease — 「이 경로는 내가 쓰는 중」

두 에이전트가 같은 폴더를 동시에 고치지 않게, 에이전트(MCP `lease_acquire`)나 터미널(`fsh lease acquire <경로> --write`)이 폴더에 **lease**를 잡습니다.
기본 30분, 최대 8시간(`lease_renew`/`fsh lease renew`로 늘림). 다른 세션이 겹치는 경로에 쓰기 lease 를 잡으려 하면 보유자 닉네임과 끝나는 시각이 나오며 거절됩니다.
lease 를 잡으려면 그 경로의 쓰기(또는 읽기) 권한이 있어야 합니다 — 없으면 에이전트가 `request_access` 로 승인을 요청합니다. 위임한 하위 세션은 같은 폴더면 부모의 lease 를 함께 쓰고,
worktree 로 띄우면 새 worktree 에 자기 lease 를 받습니다.

- **강제인 것**: 서버 설정 `VT_AUTHZ_ENFORCE` 에 `lease` 가 있을 때만, FarShell 이 대신 하는 쓰기(웹의 git stage·commit, 세션으로 보내는 파일, 위임 작업 폴더)가 남의 lease 경로에서 거절됩니다.
- **권고인 것**: 에이전트가 자기 도구로 직접 쓰는 것, 그리고 같은 사용자 계정의 다른 프로그램. **lease 는 잠금이 아니라 표시입니다** — 같은 계정의 프로세스는 무시할 수 있습니다.
- 사람은 막히지 않습니다. 남의 lease 경로에서 쓰면 기록과 알림만 남습니다.
- **커밋 guard(선택)**: `fsh lease guard install` — 남의 lease 가 걸린 파일이 든 커밋을 알려 주며 멈춥니다. 서버에 닿지 못하면 경고만 하고 커밋은 통과합니다. 기존 pre-commit 훅은 지우지 않고 이어서 실행합니다.
- 사람이 lease 를 회수하는 화면은 아직 없고 API(`DELETE /api/authz/leases/{id}`)로 합니다. 권한을 회수하면 그 권한으로 잡은 lease 도 함께 사라집니다.

## pair — 두 세션이 한 작업을 함께

두 에이전트(또는 사람 하나와 에이전트 하나)가 같은 세션·폴더 묶음을 **driver**(입력하고 씀)와 **navigator**(읽고 메시지)로 나눠 맡는 장치입니다. 서버 설정
`VT_AUTHZ_ENFORCE` 에 `pair` 가 있어야 켜집니다(꺼져 있으면 `fsh pair` 가 그렇게 알려 줍니다).

1. 한쪽이 `fsh pair start --session 이름 --dir 폴더` (또는 MCP `pair_create`) → 코드(`ABCD-EFGH`)와 **두 단어 확인 문구**가 나옵니다. 코드는 5분·한 번만 쓸 수 있고, 5번 틀리면 폐기됩니다.
2. 상대가 `fsh pair join <코드>` (또는 `pair_join`). 합류의 결과는 코드가 아니라 **자기 신원으로** `fsh pair status` 에서 읽습니다.
3. 승인함에 「pair」 요청이 한 건 뜹니다 — 묶음 전체, 두 확인 문구, 역할별로 받는 권한이 **한 화면**에 나옵니다. 두 에이전트가 보고 있는 문구와 같은지 확인하세요.
   raw 입력·세션 관리·릴레이 같은 **높은 권한**은 따로 체크한 것만 주어지고, 체크하려면 비밀번호를 다시 확인해야 합니다. 에이전트는 승인할 수 없습니다. 나중에 권한을 넓히려면 새로 승인해야 합니다.
4. driver 는 정확히 한 명입니다. `fsh pair handoff <id>` 로 제안하고 상대가 `fsh pair accept <id>` 하면 바뀝니다(2분 안에 수락하지 않으면 원래대로). 사람은 언제나 입력할 수 있습니다.
5. 끝: `fsh pair end <id>`, 사람이 권한 화면에서 회수, 2시간 유휴(`VT_PAIR_IDLE_MIN`), 구성원 세션 소멸, 8시간. 끝나면 권한·lease·구성원 간 대기 메시지가 정리됩니다 (`fsh pair revoke <id> --verify` 로 확인).

같은 사용자 계정의 프로그램은 권한 저장소를 직접 고칠 수 있습니다 — pair 는 그것을 막는 장치가 아니라 누가 무엇을 하는지 분명히 하고 사고를 일찍 끊는 장치입니다.

관련: `fsh help agent-state` (MCP 도구 `request_access`·`whoami`), `docs/ref/auth.md`.
