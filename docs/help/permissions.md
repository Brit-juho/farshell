# fsh help permissions — 에이전트 승인함과 권한

에이전트가 이 맥에서 무언가를 하려면 사람의 승인이 필요한 경우가 있다 — 공유 세션을 읽고 쓰기, 다른 세션의 에이전트에게 메시지 보내기,
다른 맥에 제어 권한 주기, 에이전트가 직접 요청한 임의의 권한. 이 모든 요청이 **하나의 승인함**에 모이고, 승인한 권한은 **설정 > 권한**에서 관리한다.
승인과 회수는 비밀번호로 로그인한 브라우저(웹/폰)에서만 된다. 터미널의 `fsh authz` 는 보기 전용이다.

## 승인 요청이 오면

- 요청이 오면 결정 창이 뜬다. 한 번에 **요청 하나**만 보이고 오래된 것부터 나온다(`1 / N`). 「모두 허용」은 없다.
- 창에는 요청한 세션(위임된 하위 세션이면 계보), 대상, 요청한 권한을 **프리셋 이름**(보기 · 협업 · 운전 · 제어)으로 말한 문장,
  그리고 정확한 scope와 조건이 그대로 나온다. 에이전트가 적은 사유가 있으면 따로 표시한다.
- 선택지는 **거부 / 한 번만 / 이 세션 동안**이다. 메시지·다른 맥 요청은 한 번만을 고를 수 없고 그 이유가 창에 적힌다.
- 오조작 방지: 기본 포커스는 「거부」, 창이 뜬 뒤 잠깐은 어떤 버튼도 눌리지 않는다, Esc·배경·X는 결정이 아니라 「나중에」다.
- **높은 권한**(raw 입력, 브라우저 JS 등)이 들어 있는 요청은 눈에 띄게 따로 표시되고, 허용하려면 비밀번호를 다시 확인해야 한다.
- 알림 문구에는 세션 이름이나 요청 내용이 들어가지 않는다.
- 「나중에」로 닫은 요청은 남아 있다. 설정 버튼의 숫자 배지(대기 건수)나 설정 > 권한 > 승인 대기에서 다시 연다.

## 설정 > 권한

| 구역 | 내용 |
|---|---|
| 승인 대기 | 모든 종류의 대기 요청 한 목록. 「결정하기」로 해당 요청의 결정 창을 연다 |
| 허용된 권한 | 주체·리소스·종류로 거르는 목록. 행마다 프리셋(또는 scope 개수), 정확한 scope·조건, 누가 어떤 경로로 승인했는지, 만료·남은 횟수, 위임 계보. 「회수」는 확인을 거친다 |
| 기본 규칙 | 코드가 정한 기본 권한. 읽기 전용이라 회수할 수 없다 |
| 감사 기록 | 최근 순. 주체·리소스·기간으로 거르고, 거부 기록 포함 여부를 고른다. 해시 체인이 정상이면 중립적인 「무결성 확인됨」, 끊겼으면 경고로 보인다. 내용(입력·화면·메시지)은 기록하지도 보이지도 않는다 |
| 비상 정지 | 사람이 아닌 주체의 모든 권한을 한꺼번에 회수하고 대기 요청을 비운다. 두 단계 확인 + 비밀번호 재확인. 사람의 로그인과 기본 권한은 그대로다 |

공유 세션 권한은 「입력만 회수」로 읽기는 남기고 쓰기만 거둘 수도 있다.

## 큐에서 막힌 항목

권한이 회수되었거나 위임이 닫혀 큐 항목이 막히면 큐 패널에 사람이 읽는 이유가 나온다(코드는 그대로 API에 있다).

관련: `fsh help agent-state` (MCP 도구 `request_access`·`whoami`), `docs/ref/auth.md`.
