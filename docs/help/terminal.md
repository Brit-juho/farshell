# fsh help terminal — 메인 터미널과 창 열기

fsh가 새 터미널 창을 열 때 **어느 앱을 쓸지 사용자가 고른다.** 특정 앱으로 고정돼 있지 않다.
값은 `~/.vt.env`의 `VT_TERMINAL`에 저장되고, CLI와 웹이 같은 구현(`server/terminal_open.py`)을 쓴다.

```bash
fsh terminal                  # 현재 설정 + 설치된 앱
fsh terminal set ghostty      # auto | ghostty | iterm | terminal | wezterm | warp | kitty | alacritty
fsh terminal unset            # 자동 선택으로 되돌리기
```

- `auto`(기본): iTerm2 → Ghostty → WezTerm → Kitty → Alacritty → Terminal.app 중 설치된 첫 앱
- 고른 앱이 설치돼 있지 않으면 `set`이 거부한다. 실행 중 열지 못하면 알린 뒤 자동 선택으로 넘어간다.
- Ghostty(1.3+)는 이미 켜진 앱에 창만 추가한다(AppleScript). 처음 쓸 때 macOS가
  「자동화」 권한을 물으면 허용한다. 거부하면 `open -na`로 폴백하지만 더 느리다.
- Warp는 명령을 자동 실행하지 못해 앱만 열고 명령을 클립보드에 복사한다(붙여넣기 필요).
- Linux는 설치된 터미널 에뮬레이터를 자동으로 고른다(`VT_TERMINAL` 지정 없음).

## 창을 여는 곳

| 어디서 | 동작 |
|---|---|
| `fsh attach [세션]` | 그 tmux 세션을 새 창에 붙인다 |
| `fsh handoff desktop` | 폰에서 보던 `dev` 세션을 맥 터미널로 가져온다 |
| 웹 「맥에서 열기」 | 서버가 있는 맥에 새 창을 연다 (같은 구현) |
| 웹 설정 「새 세션 생성 시 맥 터미널에서도 열기」 | 새 세션을 만들 때마다 창을 연다 (기본 꺼짐) |

- **창 제목은 세션 이름**이다(`server`, `dev` …). fsh 전용 tmux 서버에 `set-titles`를 켜서 만든다.
- **세션당 창 하나**: 이미 창이 붙어 있는 세션은 새로 열지 않는다.
- 명령을 `exec`로 실행하므로 tmux 세션이 끝나면 터미널 앱이 창을 닫는다. 단 **Ghostty는 AppleScript로 연 창이 프로세스가 끝나도 남는다**(직접 닫는다). 참고로 tmux의 `detach-on-destroy off` 설정이면 세션을 지워도 클라이언트가 다른 세션으로 옮겨 갈 뿐 창이 닫히지 않는다.
- `fsh start`/`restart`/`mobile`/`voice`는 창을 열지 않는다.
- 새 창이 안 열리면: 출력된 수동 명령(`tmux -L fsh new -A -s dev`)을 아무 터미널에서 실행하고,
  `fsh doctor`의 「터미널 앱」 항목과 macOS 자동화 권한을 확인한다.

## 저장된 세션과 대화 보관함

레일은 저장소 → 작업 공간 → 세션 순서로 탐색하며 「전체 세션」과 「세션 보관함」도 제공합니다.
화면을 닫아도 실행은 계속됩니다. 「작업 기록」에서는 논리 작업 이름과 실행 이력을 확인하고,
실행을 명시적으로 종료한 뒤 보관할 수 있습니다. 별도로 실행된 하위 세션은 함께 종료하지 않습니다.

「대화 보관함」의 설정에서 Claude·Codex 설정 홈을 검토하고 수집을 활성화합니다.
원본 사본과 검색용 메시지는 FarShell의 비공개 저장소에 별도로 남으므로 CLI 원본이 사라져도
이미 저장한 기록을 읽을 수 있습니다. 원본에는 민감한 대화와 도구 출력이 포함될 수 있습니다.
기본 한도는 20 GiB이며 한도에 도달하면 수집을 멈춥니다. 기존 보관본은 자동 삭제하지 않습니다.

중앙 복제는 양쪽 서버에서 페어링, 방향, 보관함 식별자와 공개키를 확인하고 별도로 승인해야 합니다.
복제 연결 해제는 이후 전송을 막으며 이미 받은 사본은 유지합니다. 복제본 열람은 원격 CLI를 실행하지 않습니다.
원본 복구와 내보내기에는 비밀번호 재확인이 필요하며, 기존 원본 파일은 덮어쓰지 않습니다.
「이어가기」로 CLI를 시작한 결과와 실제 같은 대화가 재개됐는지는 별도로 확인합니다.
현재 보관 상태의 `dependency_complete`는 거짓이며, 모든 CLI 버전의 부속 파일 복구를 보장하지 않습니다.

기존 실행 권한은 「기존 실행 권한 검토」에서 현재 실행과 대조한 뒤 다시 연결합니다.
같은 이름으로 만든 새 세션은 이전 실행의 권한을 자동으로 받지 않습니다.
복제 대상은 등록된 원본 범위로 제한할 수 있으며, 로컬 보관 한도와 복제 수신 한도는 별개입니다.
복제 키를 교체해도 전송 중이던 기록을 읽을 수 있도록 이전 키를 보존합니다.

1 MiB를 초과한 행은 검색 본문에서 생략하지만 원본 바이트는 보존합니다.
보관 상태에는 원본 전체 보존 여부와 검색 본문 생략 사유가 별도로 표시됩니다.
초과 행 뒤의 정상 메시지는 계속 색인하며, 수집을 재시작해도 진행 위치를 유지합니다.

기록 삭제에서 이 호스트만 또는 승인된 복제본 포함을 선택할 수 있습니다.
이는 열람 차단과 재수집 방지이며, CLI 원본이나 디스크의 원본 보관 바이트를 지우는 작업은 아닙니다.
연결이 끊긴 복제 호스트의 삭제 확인은 재연결 뒤 완료됩니다.
「작업 기록」은 한 창입니다. 왼쪽은 세션(상태 · 이어서 시작 · 실행 종료 · 이름 변경 · 보관, 연결된 대화, 위임 관계,
내부 서브에이전트, 실행 이력), 오른쪽은 고른 내부 서브에이전트나 위임 세션의 기록(지시 · 답변 · 도구 호출 · 도구 결과)입니다.
하위 행의 「기록 보기」·「보고 보기」와 내부 칩도 같은 창을 열고 오른쪽만 미리 골라 둡니다. 부모 위임 관계를 누르면 그 세션의 기록으로 옮깁니다.

## tmux 설정 (`fsh tmux`)

FarShell 의 tmux 는 레포의 `config/vt-tmux.conf` 를 늘 기준으로 씁니다.
내 취향(예: `set -g mouse off`)은 그 파일을 고치지 말고 `~/.config/vt/tmux.local.conf` 에 두세요.
레포 설정 맨 끝에서 읽혀 같은 옵션을 덮어쓰고, 파일이 없으면 조용히 건너뜁니다.

```
fsh tmux reload    # 떠 있는 tmux 에 설정을 다시 읽힘 (세션은 그대로)
fsh tmux status    # 지금 적용 상태
```

- 예전 설치가 남긴 `~/.config/vt/tmux.conf` 사본은 `fsh tmux reload`(그리고 `fsh sync`) 가 치웁니다.
  손대지 않은 사본은 `tmux.conf.bak-날짜` 로, 직접 고친 것은 `tmux.conf.legacy` 로 이름만 바뀌고
  지워지지 않습니다. 고친 줄은 `tmux.local.conf` 로 옮기세요.
- 다시 읽어도 설정에서 **지운** 값은 실행 중인 tmux 에 남습니다. 완전히 새로 읽히려면
  tmux 서버를 재시작해야 하고, 그러면 세션이 모두 닫힙니다.
- `fsh doctor` 의 「tmux 설정」 줄이 같은 상태를 보여 줍니다.
