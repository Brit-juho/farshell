# FarShell 실행 프로필

「MCP · 스킬 · 플러그인」의 「실행 프로필」에서 Claude와 Codex의 전용 설정
루트를 만들 수 있습니다. 한 논리 계정에 여러 프로필을 연결할 수 있지만,
같은 라벨은 제공자에서 확인한 계정 신원을 뜻하지 않습니다.

```bash
fsh profile list
fsh profile create development --tool claude
fsh profile create review --tool claude --account <account-id>
fsh profile create login-test --tool codex --test
fsh profile login <profile-id>
fsh profile status <profile-id>
fsh profile sources
fsh profile retirement
```

로그인은 해당 호스트의 대화형 터미널에서 네이티브 CLI로 진행합니다. OAuth
토큰은 기존 clauth에서 복제하지 않습니다. 웹에는 로그인 명령과 확인 결과만
표시합니다. 프로필 설정 분리는 OS 샌드박스가 아니며, 공통·프로젝트·정책 설정은
CLI 규칙에 따라 상속될 수 있습니다.

구성 가져오기는 원본을 보존하고 검토한 파일 해시를 다시 확인합니다. API 키를
포함한 복제는 Claude 테스트 프로필에서 별도 검토합니다. 키·endpoint·명시적
환경변수는 전용 파일에 권한 0600으로 보관하며 OAuth 자격증명은 제외합니다.
프로필의 명시적 인증 설정만 사용하고 서버 셸의 다른 계정 키는 상속하지 않습니다.

「API 인증 설정」에서 키·endpoint·환경변수를 별도 검토하여 변경하거나 제거할 수
있습니다. 비밀값은 다시 표시하지 않으며, 해당 프로필의 CLI를 정상 종료해야 합니다.
「사용 프로필로 전환」은 로그인·설정을 유지하고 테스트 전용 강제 만료를 끕니다.
이 전환은 clauth 대체 검증의 완료를 뜻하지 않습니다.

MCP 추가·수정·켜기/끄기, 직접 설치 스킬의 켜기/끄기, 사용자 훅 추가·제거·끄기·복원,
플러그인 구성을 관리할 수 있습니다. FarShell 상태 훅은 제거할 수 없습니다.
플러그인은 로컬 원본을 고정 보관한 뒤 digest 검토와 네이티브 설치를 거치며,
새 설치와 복구는 끈 상태로 두고 활성화를 별도 검토합니다. 공개 GitHub 저장소의
40자리 commit SHA와 하위 경로를 지정해 다운로드할 수 있으며 설치는 별도 검토합니다.
같은 마켓플레이스의 고정 의존성 묶음과 업데이트·제거·복구를 지원합니다.
Codex 업데이트는 네이티브 제거·재설치로 진행합니다.

이름 변경은 로그인·구성 revision을 보존합니다. 보관은 로그인·대화를 지우지 않으며,
실행 중이거나 미완료 작업이 있으면 거부합니다. 보관 프로필은 별도 목록에서 복원합니다.

터미널에서 `fsh profile import-config`, `import-conversations`로 같은 검토 흐름을 일괄 실행할 수 있습니다.
대화는 원본 해시와 소유 기록을 확인해 복사합니다. 소유가 불명확하거나 분쟁
상태인 clauth 공유 대화는 가져오지 않습니다. 복사 완료, Codex 네이티브 읽기,
검증된 실제 대화 재개는 서로 다른 결과입니다. clauth 대체 준비 확인은 원본별로 최근 수정된
5개 대화만 실제 재개 검증을 요구하고, 나머지는 원본 해시가 일치하는 가져오기 완료면
충족으로 봅니다. 소유 불명 대화는 제외 사실을 한계로 표시합니다. 가져오기 뒤 사용자가 수정한
파일은 되돌리기로 덮어쓰지 않습니다.

전역 공유: `fsh profile share <id>`는 전역 `~/.claude`의 스킬·에이전트·명령·훅·플러그인·`CLAUDE.md`·
대화 기록(`projects`)을 프로필 폴더에 링크로 연결합니다. 전역이 원본이라 한 곳에서 설치·업데이트하면
모든 프로필에 반영됩니다. 프로필 전용으로 남는 것은 로그인·토큰, `.claude.json`, `settings.json`과, 전역에
없거나 전역과 내용이 다른 실제 확장(스킬·에이전트·명령·훅)입니다. 전역과 같은 사본은 링크로 바꾸되 원본은
`.pre-share/` 아래로 옮기며 아무것도 지우지 않습니다. 플러그인은 설치 위치가 공유되고, 계정별로 다른 것은
설정의 켜기/끄기입니다. 대화 기록을 공유하는 프로필은 대화를 가져올 필요가 없고 재개만 검증합니다.
프로필 폴더 안의 링크는 정확히 전역의 같은 이름 항목을 가리키는 것만 허용되며, 전역 폴더가 지워지면
모든 프로필이 함께 영향을 받습니다. 프로필을 띄울 때 전역의 새 항목은 자동으로 링크됩니다.

설정 동기화: `fsh profile sync-settings <id>`(프로필을 띄울 때도 자동)는 전역 `settings.json`과
`~/.claude.json`의 MCP 서버 정의를 읽기만 하고 프로필에 키 단위로 맞춥니다. 프로필이 마지막 적용 뒤
건드리지 않은 키는 전역을 따라가고(삭제 포함), 프로필이 바꾼 키는 프로필 값이 남으며 전역이 바뀌어도
덮지 않습니다. `--take-global <키>`로 전역 값으로 되돌릴 수 있고 `--dry-run`은 키 이름만 보여 줍니다.
플러그인·스킬·훅·MCP의 켜기/끄기만 프로필마다 다르게 두고 각 플러그인의 설정, 스킬 파일, MCP 정의와
거기 든 키는 같이 쓰는 방식입니다. `fsh profile toggle <id> plugin|skill <이름> on|off`는 그 프로필만
바꾸며, MCP와 훅은 MCP·스킬·플러그인 관리 화면에서 끄면 그대로 유지됩니다. 모델, `apiKeyHelper`,
`forceLogin*`, 이름이 `ANTHROPIC_`·`AWS_`로 시작하거나 KEY·TOKEN·SECRET·HEADERS가 든 `env` 키는
계정 전용이라 어느 방향으로도 복사하지 않습니다. 훅은 FarShell 상태 훅을 빼고 이벤트 단위로 따라가며,
일부 훅을 끈 이벤트와 오래된 clauth 런타임 경로가 든 훅은 건너뜁니다. OAuth로 로그인하는 원격 MCP는
그 프로필의 설정 폴더에 로그인이 따로 저장되므로 프로필마다 한 번씩 로그인해야 합니다(refresh token을
복사하면 한 체인의 보관자가 둘이 됩니다). MCP 정의는 세션이 실행 중이면 다음에 적용합니다.

새 세션에 계정 고르기: 「+」 메뉴의 「이번만 다른 계정」으로 고른 계정의 새 tmux 세션을 만들고, 「기본 계정 바꾸기」
(또는 `fsh profile default <이름>`)로 앞으로 만드는 새 세션의 기본을 도구(Claude·Codex)별로 정합니다.
그 세션에만 그 프로필의 설정 폴더(`CLAUDE_CONFIG_DIR`·`CODEX_HOME`)가 들어가고, 고른 계정을 덮어쓰는
`ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`·`CLAUDE_CODE_OAUTH_TOKEN`·`OPENAI_API_KEY` 등은 그 세션에서 지워집니다.
실행 중인 세션은 바뀌지 않고 자동 전환도 없습니다. 폴더가 없거나 로그인이 안 됐거나 토큰이 만료된 프로필은 이유와 함께
거절하며, 기본 `~/.claude`로 대신 만들지 않습니다. 목록은 계정 이름 · 인증 상태 · 사용률과 리셋(이미 읽어 둔 값이 있을 때,
없으면 「알 수 없음」) · 갱신 시각을 보이고 「여유 많은 순」으로 정렬할 수 있습니다. 레일·세션 카드의 작은 이름표는
**만들 때** 고른 계정입니다(셸 안에서 환경을 바꾸면 달라질 수 있음). 이 맥에 직접 접속했을 때만 쓸 수 있고, 본인 계정만
등록하세요. API 엔드포인트로 설정한 프로필은 이 방식을 지원하지 않으니 「이 계정으로 바로 실행」을 쓰세요.

장기 토큰: refresh token이 없는 `claude setup-token` 값을 `fsh profile token set <id>`로 등록하면
로그인 대신 그 토큰으로 세션을 띄웁니다. 갱신할 것이 없어서 여러 세션이 같은 refresh 체인을 두고
다투다 로그아웃되는 일이 없습니다. 토큰은 권한 0600 파일에 쓰기 전용으로 두고 그 프로필의
세션에만 `CLAUDE_CODE_OAUTH_TOKEN`으로 전달하며 어떤 화면·API·로그에도 나오지 않습니다.
수명은 약 1년으로 가정하며(서버가 보증한 값이 아님) 30일 전부터 경고합니다. 이 토큰에는
사용량·계정 조회 범위가 없어 사용량 %와 계정 신원은 확인할 수 없고, 은퇴 판정의 한계로 표시합니다.
API 인증이 있는 프로필과는 함께 쓸 수 없습니다.
새 토큰 받는 길(공식): 터미널에서 `claude setup-token`을 실행하면 1년짜리 토큰을 화면에 출력합니다.
그 값을 복사해 `fsh profile token set <id>`를 실행하고 안내 줄에 붙여 넣으세요(입력은 화면에 보이지
않고 셸 기록에도 남지 않습니다). 파이프로 넘길 때만 `--stdin`을 쓰고, 토큰을 명령줄 인자로 주는 방법은
없습니다(`ps`·셸 기록에 남기 때문). clauth가 가진 토큰을 가져오는 옵션(`--from-clauth`)은 없앴습니다.

`VT_USAGE_PROVIDER=native`는 관리 프로필의 네이티브 OAuth 사용량을 읽으며
clauth 피드나 기본 Codex 자격증명을 대신 사용하지 않습니다. 정확히 일치하는 공식
HTTPS endpoint의 DeepSeek·OpenRouter 잔액, Z.ai·MiniMax international quota를
지원합니다. Alibaba·기타 endpoint·다른 지역은 미지원으로 표시하며 키를 전달하지
않습니다. Alibaba 콘솔 인증은 수집하지 않습니다. `none`은 사용량 표시를 끕니다.

「짧은 실제 호출 검증」은 Claude에서 짧은 모델 요청을 보내므로
제공자 요금이 발생할 수 있습니다. 「네이티브 갱신 검증 준비」는 테스트 로그인만
만료 상태로 바꿉니다. 실행 중인 프로필에서는 거부하며 실패하면 재로그인이
필요할 수 있습니다. 운영 프로필에는 적용할 수 없습니다.

「clauth 대체 준비 확인」은 구성·실제 호출·갱신·사용량·세션·대화 재개에서
부족한 증거를 표시합니다. 이 결과만으로 clauth를 삭제하거나 중지하지 않습니다.
원본 OAuth 프로필은 별도 검토로 기존 access token을 공식 계정 조회에만 사용하여
대상 계정과 비교합니다. 원본 토큰을 복사하거나 갱신하지 않습니다.
동시 사용 확인: 갱신되는 로그인은 같은 계정의 서로 다른 프로필 두 개가 동시에 실행될 때만 인정합니다.
갱신할 것이 없는 장기 토큰이나 API 키 프로필은 같은 프로필의 세션 두 개가 동시에 실행 중일 때 인정하며,
이 관찰은 인증 정보에 묶어 기록해 두었다가 토큰이 바뀌면 다시 요구합니다. 셸에서 실행한 확인도 서버가
기록한 세션 상태와 tmux 생존 여부로 판단합니다.

「실제 대화 응답 확인」은 Claude·Codex의 실행 신원과 완료된 응답을 관찰하며 새 요청을
보내지 않습니다. 자동 호출은 Claude만 지원합니다. 계정 동시 사용과 실제 OAuth
갱신을 검증하기 전에는 완전 대체로 판단하지 마세요.

관리 API는 [API Reference](../../API.md)에 있습니다. 대상 호스트의 사람 로그인과
변경 시 비밀번호 재확인이 필요하며 machine token·에이전트·peer 직접 변경은
허용하지 않습니다.
