# fsh help voice — 음성 입력 동작

음성 입력은 브라우저 마이크와 Voice Daemon 두 경로입니다. 음성 전용 모드는 브라우저 화면 모드입니다.

## 1. Voice Daemon (데스크톱 전역 핫키)

    fsh voice

- 백그라운드 실행. 노션/브라우저 작업 중에도 동작
- 디폴트 핫키: `Ctrl+Shift+M` (변경 가능, `fsh help hotkeys` 참고)
- 이어폰 Play/Pause 버튼으로도 토글 가능 (macOS Media Key)
- STT 후 텍스트 + Enter로 활성 tmux pane에 직접 입력 → 즉시 실행됨
- 종료: `fsh stop`

음성 타깃은 디폴트로 tmux의 most-recent active pane이지만,
`fsh voice-target <세션명>`으로 특정 세션에 lock 가능 (자세히는 `fsh help target`).

포커스가 다른 앱(브라우저 등)에 있어도 daemon은 계속 동작하기 때문에, 녹음을
시작하는 순간 "→ dev:0.0" 같은 데스크톱 알림으로 이번 발화가 어느 pane으로
갈지 미리 보여준다(lock된 경우 🔒 표시). 끄려면 `VT_VOICE_TARGET_NOTIFY=off`.

## 2. 모바일 🎤 버튼

웹 UI 보이스바의 마이크 버튼 또는 설정 「음성 및 알림」 → 현재 세션 음성의 「녹음 시작」:
- 누르면 녹음 시작, 다시 누르면 종료
- 첫 클릭은 모델 준비. 준비 완료 후 다시 눌러 녹음
- STT → 녹음 시작에 고정한 세션/pane에 입력. 중간에 탭을 바꿔도 대상 유지
- 최대 60초. 대상이 사라지면 인식 텍스트 복사 제공
- 모바일은 "현재 보는 탭 = 타깃"이라 lock 불필요

## 3. 음성 전용 모드 (🎧)

웹 UI에서 `음성 전용` 버튼. 터미널 화면을 숨기고 큰 마이크 버튼만 표시.
이어폰 운전 중 / 화면 안 보고 손으로만 조작할 때.

## TTS (음성 출력)

마이크 옆 「응답 읽기 설정」 → 현재 세션의 끔 / 완료음 / 응답 읽기. 기본은 끔입니다.
- Claude·Codex의 완료 훅과 최종 응답 어댑터를 사용합니다. 응답 끝부분 최대 200자를 읽습니다.
- 출력 위치: 이 기기 또는 서버 컴퓨터. 브라우저는 한 화면만 받고 「이 기기로 옮기기」로 바꿉니다.
- 폰이 끊겨도 서버 맥에서 대신 읽지 않습니다. 켜 둔 다른 세션도 같은 기기에서는 순서대로 읽습니다.
- 자동 재생이 막히면 「터치하여 재생」. 「소리 듣기」는 실제 TTS 테스트입니다.
- 같은 폴더에 여러 에이전트가 있으면 해당 pane에서 `fsh voice-bind <claude|codex> <대화 ID>`로 연결합니다.
- TTS auto: edge-tts(외부 서비스) → macOS say. 외부 전송을 원치 않으면 로컬 음성만 선택합니다.
- 최소 작업 시간·오류 응답 제외를 세션마다 설정합니다. 서버 출력만 화면 가시성에 따라 끌 수 있습니다.
- 음성 데몬 없이 브라우저만으로도 됩니다. 다른 도구는 응답 어댑터가 있어야 지원합니다.

「맥에서 음성만 쓰기」는 제거됐습니다. 맥 전역 단축키는 `fsh voice`를 사용하세요.
데몬도 서버 STT를 공유합니다. 독립 사용은 `VT_VOICE_STANDALONE=on`을 명시하며 입력 확인 낭독은 기본 끔입니다.
자동 연속 녹음은 없으며 매 발화는 명시적인 토글로 시작·종료합니다.

## STT 엔진과 모델

**음성 인식은 FarShell을 돌리는 컴퓨터(서버)에서 실행된다.** 폰·다른 PC·원격 접속 기기는 소리를 녹음해서
올리기만 한다. 그래서 쓸 수 있는 엔진은 서버 OS가 정한다.

모델은 설정 「음성 및 알림」의 「음성 입력」에서 고른다. 이 서버가 쓸 수 있는 모델만 카드로 보이고,
하나에 **「권장」**이 붙는다. 카드마다 한 줄 특징, 정확도(CER%)·문장당 속도·메모리 측정치, 디스크 용량,
필요한 것(패키지·실행 파일)이 표시된다. 측정은 합성 음성 20문장·Apple Silicon 기준이라 참고용이다.

| 모델 | 어디서 | 특징 |
|---|---|---|
| Qwen3-ASR 0.6B (MLX) | 애플 칩 맥 | 맥 **권장**. 영어·한글이 섞인 지시에 안정적, 약 1GB |
| Qwen3-ASR 1.7B (MLX) | 애플 칩 맥 | 정확도 최고, 메모리 약 2.5GB |
| Qwen3-ASR 0.6B (llama.cpp) | 맥·Linux·WSL2 전부 | 다른 환경의 **권장**. GPU 없이 CPU로 동작, 실험적 |
| Qwen3-ASR 1.7B (llama.cpp) | 맥·Linux·WSL2 전부 | 큰 모델, 아직 측정 안 함 |
| Apple 음성 인식 | macOS 26+ 애플 칩 | 헬퍼·한국어 시스템 자산 준비, 경량 |

**모델은 자동으로 받지 않는다.** 서버·데몬·미리 적재는 이미 받은 것만 쓰고, 없으면 「먼저 받아 주세요」로 멈춘다.
받기는 설정에서 카드를 고르고 크기를 보여주는 확인 창에서 「받기」를 눌렀을 때만 시작된다. 필요한 것은 단계별로 따로
확인한다: (1) 엔진 — llama.cpp 실행 파일(약 12~18MB)은 승인하면 앱이 공식 릴리스에서 받아 `~/.vt/engines/`에 둔다
(버전 고정, sha256 검증). pip 패키지(mlx-qwen3-asr)는 설치 명령만 안내하고 자동 설치하지 않는다.
(2) 모델 파일 — HuggingFace에서 받는다.

- **직접 입력(고급)**: 목록에 없는 모델은 엔진을 고르고 `owner/repo`를 적는다. 경로·URL은 받지 않는다.
- 환경변수 `VT_STT_MODEL`이 설정보다 우선한다. 서버와 음성 데몬이 같은 선택을 따른다.
- 안 쓰면 모델을 내려 메모리를 돌려준다(`VT_STT_IDLE_SEC`, 기본 600초). 다음 사용 때 1~4초 걸려 다시 올린다.
- llama.cpp 엔진은 별도 프로세스로 뜨고 127.0.0.1에만 열리며 실행마다 임의 키가 걸린다. 터널로 노출되지 않는다.
- 이전 버전에서 고른 Whisper 모델은 더 이상 지원하지 않는다 — 설정에 안내가 뜨고 새 모델을 다시 골라야 한다.

모델·엔진 삭제: 설정 「받아 둔 항목 관리」에서 지운다. 가중치가 폴더 밖 공유 캐시(`hub/blobs/`)에 있는 경우까지 함께
지워 공간이 실제로 돌아온다. 선택 중인 모델을 지우면 경고가 뜨고, 다시 받기 전까지 음성 입력이 안 된다.

## 녹음 전송

브라우저는 지원하는 형식(webm/opus → mp4(AAC) → 브라우저 기본 순)으로 녹음해 서버로 올린다. 서버는 어떤
형식이든 16kHz mono로 바꿔 엔진에 넘긴다. 전송이 실패하면(네트워크·5xx) 두 번 다시 보내 보고, 그래도 안 되면
「다시 보내기」 버튼으로 같은 녹음을 재전송할 수 있다. 같은 녹음이 두 번 도착해도 터미널에는 한 번만 입력된다.
서버 로그의 `voice.stt timing`에서 디코드·대기·인식 시간을 볼 수 있다.

## 자주 묻는 질문

- **Q. STT가 텍스트만 입력? 아니면 Enter도?**
  - A. 텍스트 + Enter. 즉시 실행됨. 셸에서 위험 명령 발화 주의.

- **Q. claude가 안 떠있어도 동작?**
  - A. 동작함. 활성 tmux pane이 셸이면 셸로 들어감.

- **Q. codex CLI에서도 동작?**
  - A. 동작함. claude/codex 구분 없이 활성 pane에 보냄.

- **Q. 잡음이 자동으로 입력되나?**
  - A. ❌ 안 됨. 명시적으로 핫키/버튼 토글 후 시작-종료.
