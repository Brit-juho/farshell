# API Reference

Full list of REST/WebSocket endpoints served by the FarShell server (`server/main.py`).
See [README.md](./README.md) for an overview and [ARCHITECTURE.md](./ARCHITECTURE.md) for
the architecture.

**Auth:** If a password (`fsh password`) or token (`VT_AUTH_TOKEN`) is set, every
endpoint requires authentication. Humans authenticate with the `vt_session` cookie
issued after login; daemons/scripts authenticate with an `Authorization: Bearer xxx` header (a `?token=xxx` query param
is still accepted unless `VT_AUTHZ_ENFORCE=legacy` is on, see «Shared machine token» below). See the
[Security section of README.md](./README.md#security) for the full auth model.

---

## Sessions / PTY

| Method | Path | Description |
|--------|------|------|
| GET | `/api/sessions?screen=S` | List sessions (each with `tmux_name` and `origin`, same values as `/api/tmux/sessions`); `screen` limits tmux web attachments to one browser tab. Without it, lists all sessions for CLI/legacy callers |
| POST | `/api/sessions` | Create a session (JSON: cols, rows, name) |
| DELETE | `/api/sessions/{session_id}` | Delete a session |
| PATCH | `/api/sessions/{session_id}` | Rename a session (JSON: name) — also renames the tmux session (alphanumeric/dash/underscore only) |
| POST | `/api/sessions/{session_id}/keys` | Write text straight into the PTY (JSON: `text`, optional `prompt_id`) — same privilege as typing in the terminal WS. 400 `bad_request` when the body is not JSON or `text` is missing; 409 `stale_prompt` when the `prompt_id` was already consumed; 404 for an unknown session. Used by the mobile fleet home's inline approval buttons |
| POST | `/api/sessions/{session_id}/paste` | Paste-only entry point (JSON: text) — the server decides bracketed-paste markers, newline normalization, and unsafe control-char stripping instead of the browser guessing. Same function as the WS `{"type":"paste"}` message. 404 for an unknown session |
| POST | `/api/watch/{session_id}` | Toggle output watching ON/OFF (JSON: enabled, timeout) |

## tmux

| Method | Path | Description |
|--------|------|------|
| GET | `/api/tmux/sessions` | List tmux sessions. Each item carries `origin` — where the session was created: `local` (this UI, incl. worktree open), `peer` (another Mac via `/api/peer/sessions/create`), `external` (no record, or any other value — an old `agent` option reads back as this: `fsh` CLI or plain tmux). Read from tmux option `@fsh_origin` in the same `list-sessions` call; the same field is in `/ws-workspace` `tmux_sessions`. `originHost` (string, `/api/tmux/sessions` and `/ws-workspace`) is the display name of the Mac that created a `peer` session — the label this host's peer grant carries for the caller (tmux option `@fsh_origin_host`, written with `@fsh_origin`, sanitised: no control characters/tabs, ≤60 chars); `""` when `origin` is not `peer` or the session has no record (created before this field existed). A reader that does not know the field ignores it. Also `share` (`{nick, mode}` while the session is shared with agents, else `null` — tmux options `@fsh_share_nick`/`@fsh_share_mode` read in the same `list-sessions` call, no extra tmux call; a nick that breaks the rule reads as `null`, an unknown mode as `read`; also in `/ws-workspace` `tmux_sessions`), `webScreens` (web screens attached — PTYs this server holds for the session, one per browser tab/phone) and `otherClients` (`attached` minus `webScreens`, floor 0: non-web attaches such as a Mac terminal); both come from the same `list-sessions` call plus the session store, no extra tmux call; `command`, `cwd`, `pane_id` refer to the active pane in the active window. `context` is one Git snapshot of `contextCwd` — the agent CLI's cwd from its latest hook when that CLI runs in the session and the path is readable (`contextSource: "agent"`, so a CLI that moved into a linked worktree shows that worktree's branch), else the pane `cwd` (`contextSource: "terminal"`; older servers omit both fields). Shape: `{status: ready|nonrepo|unavailable, cwd, root, branch, changed: {files, add, del}|null, worktree: {kind: main|linked|unknown, status: ready|unavailable, name, relative, repositoryRoot}|null}`; branch and change counts are from the same cwd, independent of agent CLI or creation-time `wt_id`. `worktree` is resolved from the current Git directory/common directory, including CLI-created trees; `name` is the workspace root basename (shortest distinct parent suffix for duplicate names in the snapshot), `relative` is the resolved cwd path beneath `root` (empty at root), and `repositoryRoot` is the allowed primary workspace path or null. Git management paths are never returned. Identity lookup failure yields `unknown/unavailable` without discarding valid branch/diff data; no Git root yields null. An unavailable lookup keeps only the same cwd's last success, never another cwd; denied paths lose cached Git values. REST and `tmux_sessions` push share the collector (10s Git cache, 2s retry, default 5s visible-screen scan). `profile` / `profiles` — the account(s) FarShell injected when it created the session (`{id, name, tool}`; `profile` is the first, Claude before Codex, `null` when none; `name` is `null` if the registry cannot name the id): read from tmux option `@fsh_profile` in the same `list-sessions` call, names come from the profile registry only when a tag exists. It records the account **at creation** — a person can still change the environment inside the shell. Also in `/ws-workspace` `tmux_sessions`. `lineage` is set only for a delegation sub-session: `{delegation, parent (current name or null), state: running|reported|closed|orphaned, outcome, createdAt, task, summary (≤600 chars)}`, from the delegation ledger by `#{session_id}:#{session_created}` (not from `@fsh_parent`) |
| POST | `/api/tmux/attach` | Attach to a tmux session (JSON: name, optional 32-hex `screen`). Each screen gets its own PTY; the same screen reuses its attachment after reload |
| POST | `/api/tmux/create` | Create a tmux session + auto-attach (JSON: name, cols, rows, cwd, optional `screen`, optional `unique_name`). No name → named after the `cwd` folder (else the server's), a taken name gets `-1`, `-2`. With `unique_name` a taken `name` also gets `-1`, `-2` instead of failing, and the name is reduced to `[A-Za-z0-9_-]` (nothing left → the default name); the response's `tmux_session` is the name actually used. Optional `profile` (account choice for this session only): a profile id, `"default"` (each tool's explicitly marked default; none marked = nothing injected) or `"none"`; absent = today's behaviour, nothing injected. **A browser login session only** — a machine token, peer, unix socket or agent gets `403 human_session_required` as soon as the field is present. The session gets that profile's `CLAUDE_CONFIG_DIR` / `CODEX_HOME` plus `FSH_PROFILE_ID` in its own tmux environment (a long-lived-token profile also `CLAUDE_CODE_OAUTH_TOKEN`, passed through a one-use 0600 tmux config file read by `source-file`, so it is never in a command line or log), and the overriding variables are **unset** in it (Claude: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN` unless the profile supplies its own, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`; Codex: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_ORG_ID`), whether they come from the server's or tmux's global environment. tmux option `@fsh_profile` (ids, comma-separated) and a row in the registry's `injected_sessions` record it. Running sessions are never touched. **No fallback**: a profile that does not exist, is archived or not `ready`, has a missing/unsafe folder, is not logged in, has an expired/unreadable token, or uses an API-endpoint setup is refused and no session is created — `400 {error:"invalid_profile"}` for a malformed value, otherwise `409 {error, reason}` with `error` one of `profile_not_found`, `profile_archived`, `profile_not_ready`, `folder_missing`, `folder_unsafe`, `not_logged_in`, `token_expired`, `credentials_unreadable`, `unsupported_auth`, `default_invalid`, `token_missing`, `profile_unavailable`. Success adds `profile`, `profiles` (`{id,name,tool}`) and `cleared_env` (names of overriding variables that existed and were removed) to the response. Needs tmux 3.2+; also works with `operation_id` (the profile is part of the operation's idempotency fingerprint) |
| DELETE | `/api/tmux/kill/{tmux_name}` | Fully kill a tmux session |
| POST | `/api/tmux/kick` | tmux hooks only — nudges the session-list watcher. Needs the `X-VT-Kick` secret the server makes at start (not the login); 204, or 403 without it |
| POST | `/api/tmux/open-on-mac` | Attach an existing tmux session in a new window on the server's (macOS) terminal (JSON: name). Returns 400 if the server isn't macOS |
| POST | `/api/tmux/{name}/share` | **Browser login session only.** Share a session with agents (JSON: `nick` `[A-Za-z0-9_-]{1,32}`, unique across sessions case-insensitively → 409 `nick_taken`; `mode` `read`\|`readwrite`). Calling it again on the same session changes the nick or mode — lowering the mode takes effect on the very next agent call. 400 `bad_nick`/`bad_mode`, 404 unknown session. Returns `{ok, name, share:{nick, mode}}`. Agents can never call this (see "Agent session sharing") |
| DELETE | `/api/agent/share/sessions/{name}` | **Browser login session only.** Stop sharing — also deletes every grant and pending/denied request for that session. The distinct path avoids the tmux kill route when a shared session is renamed `kill`. Returns `{ok, name, revokedGrants, clearedRequests}` |
| GET | `/api/tmux/preview/{tmux_name}?lines=20&ansi=1` | Capture recent tmux pane output for the Grid view |
| GET | `/api/tmux/clients?session=X&me=Y` | Clients attached to a session. Each web tab has a distinct tmux client. `me` is that tab's web session id — the server derives its tty and marks `is_me` |
| POST | `/api/tmux/detach-client` | Detach one client (C1, JSON: tty, me). Detaching yourself returns 400 — there'd be no way back |
| POST | `/api/tmux/clients/solo` | "Keep only this screen" (C2, JSON: session, me). The client never sends a tty to keep — the server derives it. Returns 400 if it can't, rather than detaching everything |

## Voice

| Method | Path | Description |
|--------|------|------|
| POST | `/voice/target` | Freeze authenticated caller's input target. Body `{session_id}` (web) or `{pane}` (machine daemon); returns `{token,key,name,pane,generation,boot,ttl_sec,max_record_sec}`. Token expires after 180s; a deleted/replaced pane is never replaced with the active pane |
| GET | `/voice/defaults` | Defaults copied when a session first requests voice policy; initial mode off. Browser ownership must be claimed separately |
| PUT | `/voice/defaults` | Body `{policy}` using session policy fields; existing session overrides are unchanged |
| GET | `/voice/session?session_id=X` | Session voice policy and ownership: `?session_id=X&screen=Y`; returns `{target,policy,owns,claimed,status,adapters}` |
| PUT | `/voice/session` | Set session-specific voice policy. Body `{session_id,screen,policy,transfer?}`. Policy `{mode:off|sound|speak,destination:browser|server,min_sec,success_only,only_unfocused,engine:auto|edge|local}`; another screen's browser ownership requires explicit `transfer:true`. Settings persist outside checkout, mode 0600 |
| POST | `/voice/bind` | Machine-only explicit tool conversation binding from its actual FarShell tmux pane: `{tool:claude|codex,run,pane,tmux}`. CLI `fsh voice-bind` supplies the shell's pane/socket |
| POST | `/voice/test` | Test actual TTS through the session output queue: `{session_id,screen}`. Browser tests require that screen's playback ownership |
| WS | `/ws-voice` | Authenticated destination-specific audio. `?screen=Y`; `voice_connected` supplies a connection generation. `voice_audio` carries playback/completion IDs, session key/name, generation, actual MIME and base64 audio in one message. Client sends `voice_ack` (`blocked|played|failed|cancelled`), `voice_barge {pause}` and `voice_visible {keys}`. A single owner gets audio; reconnect does not replay past audio |
| POST | `/voice/input?session_id=X` | Voice → STT → session input. Body is the recording (`Content-Type`: `audio/webm` · `audio/mp4` · `audio/ogg` · `audio/wav`). New clients use `X-Voice-Target` from the recording-start target and `X-Voice-Id` (caller + target/content dedup, collision 409, max upload 4MiB). Legacy session-id requests remain compatible. Optional `X-Voice-Id` header: a re-sent recording with the same id is answered from memory (`duplicate: true`) and typed into the terminal only once. Returns `{text, injected, session_id, timing: {decode_ms, wait_ms, load_ms, stt_ms, total_ms}}`; `error` when the model is not ready (nothing is ever downloaded here); 429 when too many requests are queued. **Confirm step:** a client that can draw a confirm screen sends `X-Voice-Confirm: 1`. When the setting `voice.confirm` (`off`\|`shell`\|`on`, default `shell`) says the text needs confirming (plain shell or unidentifiable pane for `shell`, always for `on`, and any risky command such as `rm -rf`, `sudo`, `curl … \| sh`, `git push --force` unless `off`), nothing is typed and the response adds `pending_confirm: true`, `confirm_token`, `confirm_reason` (`shell`\|`unknown`\|`always`\|`dangerous`), `confirm_ttl_sec` (300) and `target_name`. Callers without the header (voice daemon, old clients) keep typing straight in, except that risky commands are refused with `error` (unless `off`) |
| POST | `/voice/chunk?seq=N[&final=1]` | PCM chunk upload (lets a long recording survive a network drop). Body: raw PCM16 little-endian, 16kHz mono, `Content-Type: application/octet-stream`. Headers `X-Voice-Id` (required, same rules as `/voice/input`), `X-Voice-Target` (required, token from `/voice/target`; must belong to the caller and be unexpired) and optional `X-Voice-Confirm: 1` (the client can draw a confirm screen; the web client sends it on every chunk, and it counts for the whole recording once any chunk carried it). `seq` is a decimal integer 0..3999, counted from 0. Chunks are joined strictly in `seq` order: a repeated `seq` is ignored (same bytes) or 409 `seq_conflict` (different bytes) and the cumulative ack is returned again; a chunk that arrives before its predecessors is held (at most 1000 chunks / 30 s of audio, else 409 `too_many_pending`). `final=1` marks the last chunk (an empty body is allowed only on the final one); the recording completes when every `seq` up to the final one has arrived, in any order, and that request returns the same result as `/voice/input` (`text`, `injected`, `session_id`, `timing`, `error`) plus `complete:true` (`duplicate:true` when it is a repeat; the text is typed into the pane once). The `/voice/input` **confirm step** applies unchanged: with `X-Voice-Confirm: 1` and a `voice.confirm` verdict that needs confirming, nothing is typed and the result adds `pending_confirm`, `confirm_token`, `confirm_reason`, `confirm_ttl_sec` and `target_name` (use `/voice/inject` with the same `X-Voice-Id` as `voice_id`); without the header, risky commands are refused with `error` unless `off`. A repeat of a pending recording returns the same `confirm_token` and issues no new one. Incomplete: `{ackSeq, complete:false}` where `ackSeq` is the highest `seq` joined without gaps (-1 if none), plus optional live fields read from the settings when the recording starts (fixed for that recording): `endpoint:true` when `voice.autoStop` is on and the server's energy VAD has confirmed speech (300 ms) followed by 1 s of silence (the client should then send its final chunk; the server never ends a recording itself, and never sets it without confirmed speech), and `partial:{text, seq, clipped}` when `voice.partialResults` is on (default) — the latest preview recognized from the last 20 s up to chunk `seq` (`clipped` when earlier audio was left out). A partial is display-only, never typed into the pane, skipped while the STT engine is busy, and dropped once the final chunk completes the recording. Limits: odd or >5 s (160,000 B) chunk 400 `odd_length` / 413 `chunk_too_large`; empty non-final chunk 400 `empty_chunk`; bad `seq` / `final` / voice id / missing target 400; expired or foreign target 409 `target_expired`; total over 60 s (1,920,000 B) 413 `too_long` (the recording is discarded); no request for 30 s, replaced by the same caller's newer recording, or cancelled → 410 `voice_expired`; a different target token for a recording in progress 409 `target_mismatch`; a repeated final whose recognition is still starting 409 `busy`; 429 when too many recordings are held or the STT queue is full (the chunks are kept, so re-sending the final retries recognition). One open recording per caller. Errors are `{error, code}`. A finished recording's result is kept 120 s for re-sent requests |
| POST | `/voice/chunk/cancel` | Discard an in-progress chunk recording (idempotent). Header `X-Voice-Id` or JSON `{voice_id}`. Returns `{cancelled, state}`; `state` is `cancelled`, `finishing` (recognition already running, cannot stop) or `unknown`. Late chunks of a cancelled id get 410 |
| POST | `/voice/inject` | Type confirmed text into the pane a `confirm_token` was issued for. Body `{token, text, voice_id}`; `voice_id` must equal the recording's `X-Voice-Id`. The token is single-use, 300s, and only the principal it was issued to can use it (unknown, expired and foreign tokens all give the same 409 `expired`). Control characters are stripped, text is trimmed and limited to 4000 characters (400 `empty`, 413 `too_long`). The target pane is re-validated; if it is gone, nothing is typed anywhere else (409 `target_gone`, token dropped). Concurrent use of one token: 429 `busy`; a repeat after success returns `{injected: true, duplicate: true}`; 502 `send_failed` may be retried with the same token. Success: `{injected: true, text, name}` |
| POST | `/voice/output` | Text → TTS → returns audio |
| POST | `/voice/cancel` | Pause/resume that authenticated screen's queue: `{screen,pause}`. Machine daemon may use `{server:true,pause}`. Stops only FarShell-owned playback, never global say/afplay processes |
| POST | `/voice/local/start` | Deprecated: 410 `local_mic_removed`; use browser microphone or Voice Daemon |
| POST | `/voice/local/stop?session_id=X` | Deprecated: 410 `local_mic_removed`; never records or injects |
| GET | `/voice/stt/status` | STT state — selected model, `selected_ready` (downloaded and requirements met, so it can be loaded), loaded model/engine, memory, current setup job, last error. Does not load a model |
| GET | `/voice/stt/catalog` | Models this server can run (recommended one first, readiness, requirements, measured numbers) and the ones it cannot (with the reason), plus usable engines and the current selection. `?custom=<custom:engine:owner/repo>` adds that custom model |
| POST | `/voice/stt/setup` | Start ONE preparation step in the background — body `{"model": "<id>", "step": "model" \| "req:<requirement id>"}`. The settings UI calls this only after the user confirms the download. 400 for unknown models/steps or items the app does not install itself (pip packages), 409 while another step runs. Progress is `setup` in `GET /voice/stt/status` |
| GET | `/voice/notify/clients` | Number of web clients attached to `/ws-notify` — the Stop hook uses it for "don't notify while the web UI is open" |
| POST | `/voice/stt/preload` | Load the selected model into memory (never downloads; `error` explains what is missing) |
| POST | `/voice/stt/unload` | Unload the model and give the memory back (a llama.cpp engine process is terminated) |
| GET | `/voice/stt/model` | Downloaded models (size in bytes, which one is selected) and engine programs the app downloaded |
| DELETE | `/voice/stt/model` | Delete a downloaded model — body `{"model_id": "..."}` — or the app-downloaded llama.cpp — body `{"binary": "llama-server"}`. Shared weight files outside the repo folder are removed too (unless another model uses them); returns `freed_bytes` |

## Auth

| Method | Path | Description |
|--------|------|------|
| POST | `/api/auth` | Login — password (+ `otp` for a new device) or a one-time `ticket` → issues `vt_session`/`vt_device` HttpOnly cookies. Optional `remember` (`90d` default / `24h` / `1h`) sets a **new** device's lifetime; a registered device ignores it, a ticket follows its own bound lifetime. The session never outlives its device (`min(24h, device remaining)`). 400 `invalid_remember`, 401 `invalid` (wrong password), 429 `password_locked` (with `retry_after`; `scope: "new_device"` for a new device), 401 `otp_required`/`otp_invalid`, 429 `otp_locked` |
| GET | `/api/auth/status` | Whether auth is active / OTP is linked / this device is registered and not expired (accessible unauthenticated, no secrets included). The login screen shows the lifetime choice only when `device_known` is false. Also carries the server display language `lang` (`ko`/`en`) |
| POST | `/api/auth/logout` | Clears the session only (device registration is kept) |
| POST | `/api/auth/elevate` | Re-verify password (+ OTP if linked) → reissues `vt_session` with a 15-minute `elev` claim. Session-scoped, not device-scoped. 401 `invalid`/`otp_required`/`otp_invalid`, 429 `*_locked` |
| GET | `/api/auth/elevation` | Current session's elevation state (`elevated`, `elevated_until`) + `unused: true` / `unused_reason: "ADR-27"` — `unused: true` only means no git push/PR path exists. Elevation is still required by port exposure, file-share links, MCP writes, git accounts and agent profiles (`server/routes/ports.py`, `share.py`, `mcp.py`, `git_accounts.py`). Read-only (Settings → Security) |
| GET | `/api/devices` | Registered devices (`~/.vt/devices.json`): id (first 8 chars only), label, added_at, last_seen, `current` for the requesting device, `expires_at`/`expired`/`kind` (`persistent`/`temporary`)/`method`, and display-only `os`/`browser`/`ip_last`/`via` (`tunnel`/`tailscale`/`lan`/`local`/`direct`). Expired devices stay listed for 7 days. The raw UA is not returned. Read-only — registration/revocation is `fsh device` |

**Pre-auth failure limit (all HTTP routes except the unix socket).** Failed credential attempts are counted per source: an invalid
cookie, token or login, a wrong one-time ticket or pairing ticket, and a failed peer signature. Ten failures within 60 s lock that
source for 5 minutes: every protected route (and the login and pairing endpoints, even with the right credential) answers
**429 `rate_limited`** `{error, reason:"source_locked", retry_after}` with a `Retry-After` header; the login page and static files
stay open. `/api/auth` and `/api/peer/pair` also share a global cap of 300 calls per minute across all sources
(`reason:"exchange_cap"`). Nothing is counted for a request without credentials or for a correctly signed session cookie that has merely
expired. The source is the client address; with `VT_TRUST_PROXY=1` the proxy-reported address, and for a loopback connection that
carries `CF-Connecting-IP`/`X-Forwarded-For` (a tunnel) that header value. State is in memory and resets on restart. The unix socket
is never limited. Denied and failed attempts are written to `~/.vt/audit/denials.jsonl`, not to the hash-chained audit.

## Code Viewer / Diff (read-only)

| Method | Path | Description |
|--------|------|------|
| GET | `/api/fs/roots` | List of browsable roots (default `~/GitHub`) plus `home` (the user's home directory, used to resolve `~/` terminal links) |
| GET | `/api/fs/tree?path=X[&depth=0-2][&after=C][&limit=N]` | Directory listing, one **page**: `{path, entries:[{name, dir, size, mtime?}], total, next, capped, truncated}`. The whole directory is scanned (up to 50,000 visible entries — `capped:true` past that), sorted folders first then by `name.casefold()`, then cut into pages of `limit` (1–1000, default 1000). `next` is the cursor for the next page (base64url of the last entry's sort key) or null; pass it back as `after` (a malformed one → 400 `bad_cursor`). `total` counts the scanned visible entries; `truncated` (kept for old clients) means more exists than this reply holds. Files carry `mtime` (ms); folders are not stat'ed. Excludes `.git`/`node_modules` etc. and deny-listed names on every page. `depth` (first page only) prefetches subdirectory listings into each entry's `children` (capped by dir count, and only folders with at most 200 entries). The listing can change between pages (duplicates or gaps); clients start again from the first page after a change notice |
| GET | `/api/fs/search?q=X` | Fuzzy filename search (command palette `/` mode). `path=` scopes to a subtree, max 50 results → `{results:[{name,path,…}], truncated}`. When the scan hits its 10s deadline the answer is still 200, with `{results:[], truncated:true, timeout:true}` |
| GET | `/api/fs/grep?q=X[&path=P][&mode=literal\|regex][&case=1][&word=1][&glob=G][&sid=S]` | File **content** search (palette `?` mode, sidebar 「Files › Search contents」). Authenticated (`auth()`); relayed to other hosts (group `fs`). `path` must be a directory inside the browse boundary (403 `denied` outside it or under a hidden/deny-listed folder, 404 for a file); empty `path` searches every start root. `mode` defaults to `literal`; `regex` is Python `re` syntax. `case=1` matches case, `word=1` whole words. `glob` is comma-separated (commas inside `{a,b}` don't split): plain patterns include, `!pattern` excludes; a pattern without `/` matches any path segment (`*.ts`, `docs`), one with `/` is anchored at `path` and also matches a leading folder (`src/app` = everything under it). Empty `q` → `{results:[]}`. 400: `bad_mode`, `bad_query` (over 1000 chars, newline or NUL), `bad_regex` (`reason` names the character, `pos` is 0-based), `empty_match` (a regex that matches empty text), `bad_glob` (over 32 patterns or 256 chars). → `{root, roots, results:[{path, rel, line, col, text, ranges:[[a,b]…], cut?}], files, total, searched, skipped:{large, binary, excluded, denied, unreadable}, limit, truncated, timeout, dropped, engine, elapsed_ms}` in file then line order. `col` (1-based) and `ranges` (into `text`) are UTF-16 units; a line over 500 characters is cut around its first match and `cut` gives the UTF-16 length removed in front. One engine (`scan_worker` child process): in a git work tree the candidates are `git ls-files --cached --others --exclude-standard` (`.gitignore` is respected), otherwise the filename-search walk; deny-listed names, deny folders, hidden folders and excluded folders are dropped **before** reading; files are opened with `O_NOFOLLOW` (symlinks are never followed); files with a NUL in the first 8 KB are skipped as binary. Limits: 10 s deadline (the answer is still 200 with what was found and `timeout:true`), 200 MB read in total, files over 2 MB skipped, 500 result lines, 1 MB of output — `limit` names the one that stopped the search (`results`, `bytes`, `output`, `files`). Every result file is re-checked with the full boundary rule before it is returned (a folder swapped for a symlink after the check is dropped, counted in `dropped`). A client (credential + `sid`) runs one search at a time: a new request cancels the previous one (that one answers 409 `cancelled`), and a dropped connection kills the search process. At most 2 searches run at once → 503 `grep_busy`; if the search process can't be started the answer is 503 `grep_unavailable` (it never falls back to searching in-process, which would lose the deadline); both carry `Retry-After` |
| GET | `/api/fs/grep/progress?sid=S` | Progress of the content search that is running for this client (same credential + `sid` as the `/api/fs/grep` request). Authenticated; relayed (group `fs`). ## Multi-host peering

Endpoints another Mac's FarShell server calls. Deliberately a **separate namespace**:
a peer credential reaches only what is defined here, never the rest of the API.
`TokenAuthMiddleware` skips the /api/peer prefix (a peer has no browser session cookie);
`server/routes/peer.py` verifies HMAC signatures itself.

Auth headers on every call except `pair`: `X-Peer-Id`, `X-Peer-Ts`, `X-Peer-Nonce`,
`X-Peer-Sig` = `HMAC(secret, "METHOD\npath\nts\nnonce")`. **The secret is never sent.**
60-second window, one-time nonce (replay-blocked), and the signature is bound to
method+path so a `view` GET signature can't be reused on a `control` POST.

| Method | Path | Description |
|--------|------|------|
| POST | `/api/peer/pair` | Redeem a one-time pairing ticket (JSON: ticket, id, label, version) → per-connection secret. The only unsigned peer route — the ticket is the auth, since no shared secret exists yet. Rejects reserved ids (`local`/`self`/`me`) **without consuming the ticket** |
| GET | `/api/peer/ping` | Signed liveness check → id, label, version, `serverTime` (the caller derives clock skew from it), and the caller's granted level |
| GET | `/api/peer/sessions` | Signed, `view` level — this host's tmux sessions + agent status. Also `originHost` (the creator's label as **this** host's grant records it; `""` when `origin` is not `peer` or unrecorded; an older peer omits it). **Never relays other peers' sessions** (hop 0): A↔B mutual pairing would otherwise recurse A→B→A |

## Agent session sharing (agents work only in sessions the user shared)

Two audiences, two kinds of caller. **Agent endpoints** take the machine token (`Authorization: Bearer`) **plus caller identity** (below). **User endpoints** take the **browser login session cookie only** — the machine token, `?token=`, a peer signature or an unauthenticated call all get **403 `human_session_required`** (`auth.require_human_session`, the same dependency on the whole router). An agent holds the machine token, so it must never be the thing that approves its own access. None of these paths is in the host-switch relay allowlist, and the peer namespace has no route for them: other Macs cannot use the feature.

**Caller identity (agent endpoints).** The MCP process sends `X-Fsh-Pane` (`$TMUX_PANE`), `X-Fsh-Tmux` (`$TMUX`) and `X-Fsh-Pid` (its own pid), percent-encoded. The server checks that the socket is FarShell's, that the pane exists in FarShell's tmux, and that the **caller's process-parent chain (max 64 levels) reaches that pane's `pane_pid`**; on a direct loopback connection it also resolves the real TCP peer pid with `lsof` and uses that instead of the claimed pid. Any failure → **403 `identity_unverified`** with a reason; outside tmux (no `TMUX_PANE`) is refused too. The caller's session is identified by `#{session_id}` + `#{session_created}`, never by name.

**Engine enforcement (`VT_AUTHZ_ENFORCE=share`, off by default).** Same endpoints, status codes and body keys. What changes: `read`/`send` responses, `decision` and `DELETE …/grants/{id}` responses gain **`grantId`** (the engine id, `ag-<id>`; `DELETE` accepts either form); a failed audit write stops share/unshare/decision/revoke with **503 `audit_unavailable`** (nothing is saved); an engine failure on an agent read/send is **503 `authz_unavailable`** (fails closed); a change that would write an unreadable store file (engine or the mirrored `agent_grants.json`) is **503 `store_unreadable`** — the file is left untouched (also with the flag off, for `agent_grants.json`); `GET /api/agent/share/audit` reads the hash-chained authz audit, where a successful `read`/`list` is recorded once per 10 minutes per agent and nick. Machine-token routes outside this feature (`/api/sessions/{id}/keys`, `/api/queue`, …) are not part of this feature; `VT_AUTHZ_ENFORCE=legacy` closes them to the machine token (see «Shared machine token»).

**Agent-to-agent messages under the engine (`VT_AUTHZ_ENFORCE=msg`, off by default).** The approval inbox is shared: `GET /api/agent/share/requests` also lists message requests (`kind:"msg"`, id `ms-…`, `target.name` = the receiving session), `POST …/requests/{request_id}/decision` approves (`decision:"allow"`, `level` ignored) or denies one and returns `grantId` (`gm-…`), `GET /api/agent/share/grants?kind=msg` lists message permissions (`[{id, kind:"msg", granted, updated, approvedBy, approvedVia, agent:{name,id}, target:{name,id}}]`; the default listing is unchanged), and `DELETE /api/agent/share/grants/{gm-…}` revokes one (the next send is pending again). All of these are browser-session only; an agent or the machine token gets 403. A permission belongs to one (sending session -> receiving session) pair and disappears when either session is gone. Message text is never written to the audit log (length and sha8 only). `docs/ref/auth.md` «Agent messages under the engine».

**Host permission requests (`VT_AUTHZ_ENFORCE=peer`, off by default).** The same inbox also lists requests made by `fsh host allow-control|allow-agent` (`kind:"peer"`, id `pr-…`, `change` = the requested action, `target.name` = the Mac's id); `POST …/requests/{request_id}/decision` applies (`allow`) or refuses (`deny`) one. Only a person decides — `allow-control` needs a re-authenticated person (403 `elevation_required` otherwise). The response carries `grantId` (`pg-<id>` for the control level, `pm-<id>` for agent messages). See `docs/ref/auth.md` «Other Macs under the engine».

### Shared machine token (`VT_AUTHZ_ENFORCE=legacy`, off by default)

With the flag on, the shared machine token (`VT_AUTH_TOKEN`) is not an all-purpose key. A request counts as a machine-token request when it is authenticated by `Authorization: Bearer`, a cookie whose value is the token, or `?token=`; browser login sessions and the unix socket are unaffected.

| Situation | Answer |
|---|---|
| Machine token on a (method, path) listed in the «Unix socket» table below | Works as before (and is counted in the 24h usage line of `fsh doctor`) |
| Machine token on any other route (`/api/sessions/{id}/keys`, `/api/queue` writes, the host operation routes, file and git writes, WebSockets …) | **403 `legacy_token_scope`** `{error, reason}`; the reason points at the unix socket or the web login. Counted separately for `fsh doctor` |
| `?token=…` on any protected route | **400 `token_query_unsupported`** (valid or not) |
| The token value sent as the `vt_session` cookie | **401 `token_cookie_unsupported`** |
| Token only, no web password: a call that would create an approval request (session sharing, agent messages to an unrelated session, `fsh host allow-*`) | **403 `approval_unavailable_no_password`**; set a password with `fsh password`. Grants that already exist keep working |
| Token only, no web password: a signed cookie | Authenticated, but not a person: person-only routes answer 403 `human_session_required` |

A server with neither password nor token is unchanged. Access logs mask `token`-like query values. Details and how to migrate scripts: [`docs/ref/auth.md`](./docs/ref/auth.md) «Shared machine token».

## Approval inbox, grants and audit (authz API)

One surface over every kind of approval. The five kinds (`share`, `msg`, `peer`, `generic`, `pair`) share one list and one decision route: `share` (an agent wants a shared
session — the share routes above keep working and call the same functions), `msg` (agent-to-agent message, `VT_AUTHZ_ENFORCE=msg`),
`peer` (`fsh host allow-*`, `VT_AUTHZ_ENFORCE=peer`) and `generic` (an agent asks for any (resource, scopes) with `POST /api/authz/requests`).
No new flag: these are read and management routes over the engine's existing state, and they are safe with every enforcement flag off. A
`generic` grant only takes effect where an enforcement point asks the engine (today: shared-session read/input with `VT_AUTHZ_ENFORCE=share`).
Responses never carry screen text, input or message bodies. Three kinds of caller:

- **Browser session only** (decide, revoke, panic, shadow): other callers get 403 `human_session_required`. `panic` also needs an elevated session (401 `elevation_required`).
- **Browser session or the `fsh` CLI on the unix socket** (the three `GET` reads): the CLI is a `cli` caller outside any tmux pane, read only. Anything else is 403 `human_session_required` (TCP) or `human_or_cli_required` (socket).
- **Agent** (`/requests`, `/my-grants`, plus `whoami` on the socket): a verified pane — over the unix socket the kernel-checked caller, over TCP the usual `X-Fsh-Pane`/`X-Fsh-Tmux`/`X-Fsh-Pid` identity (403 `identity_unverified`). An agent only ever sees its own records.

|--------|------|------|

| GET | `/api/authz/whoami` | Socket only — see the «Unix socket» table |
| GET | `/api/authz/shadow?limit=100` | **Browser session only.** Debug view of the shadow engine (see «Agent session sharing») |

**Deny log.** Denials (policy refusals, rate limits, lockouts, authentication failures) go to `~/.vt/audit/denials.jsonl` (0600; 1 MB × 3 files; at most 60 lines a minute, followed by a `denylog.dropped` line with the count of dropped lines; a write failure never blocks the request). The hash-chained `authz.jsonl` keeps allows and every authz/pair/lease/grant change, including a person's refusal of a request. History is not rewritten: denials already in the chain stay there. `GET /api/authz/audit` and `GET /api/agent/share/audit` read both.

## Pairs (`/api/pairs`)

Two participants work on one bundle of sessions and folders as **driver** and **navigator**; a person approves the whole pairing once. The
routes exist whatever `VT_AUTHZ_ENFORCE` says, but **without the `pair` token every one of them is `409 {error:"pair_disabled"}`** and nothing
else changes. Rules, roles, handoff, ending and the same-user caveat: `docs/ref/auth.md` «Pairs». Callers: an agent or the terminal's `fsh`
over the unix socket, or a logged-in browser; hooks, service daemons and peers are 403 `request_not_allowed`. Not on the relay allowlist.
Errors are `{error, reason, …}`. A pair view never contains session keys, principal ids or code values — names, roles, states only.

| Method | Path | Notes |
|---|---|---|
| POST | `/api/pairs` | Create: `{sessions?:[name\|key\|{local}\|{host,session}], dirs?:[absolute], leases?, elevated?:["raw_input"\|"session_manage"\|"relay"\|"browser_js"\|"browser_sensitive"], role?:"driver"\|"navigator", with?}` (at least one session or folder). Callers: a person, or an agent with `pair.manage` on `pair:*` (403 `forbidden` + `need` otherwise). `201 {ok, pair, reused:false}`; the same creator and bundle while unjoined returns `200 … reused:true`. 400 `empty_bundle`/`bad_bundle`/`bad_elevated`/`bad_role`/`bad_ref`, 403 `outside_roots`, 404 `session_not_found`, **501 `pair_remote_unsupported`** (a `{host, session}` of another Mac), 429 `too_many_pairs` (5 live per creator) |
| POST | `/api/pairs/{pair_id}/code` | Creator only (else 404). `{ok, code:"ABCD-EFGH", phrase:"two words", expires, ttl:300, reused, pair}`. A pending code is returned unchanged (`reused:true`); new codes are limited to 10 per creator per hour (429 `rate_limited`). 409 `bad_state` once joined |
| POST | `/api/pairs/join` | `{code}` (case, spaces and hyphens ignored). A verified agent session only. `200 {ok, pair:{…, phrase, pendingApproval:true}}`. Wrong or expired or spent code: `404 invalid_code` — and the attempt counts against every pending code, the 5th burns them. 400 `self_join`, 403 `not_intended` |
| GET | `/api/pairs/{pair_id}/status` | A participant (or a person); anyone else 404. `{ok, pair:{id, state, generation, members:[{seat, kind, name, role, joined, you, driver}], bundle:{sessions:[{name}], dirs, leases, elevated:{requested, granted}}, approval:{state:"none"\|"pending"\|"allowed"\|"denied"\|"cancelled", id}, role, isDriver, expires, endReason, handoff:{to, by, expiresIn}\|null, phrase?, code?:{state, expiresIn}, cleanup?}}`. States: `proposed`, `code_issued`, `joined`, `active`, `handoff_pending`, `ended`, `expired`, `revoked`. The joiner reads the approval result here — no token is involved |
| GET | `/api/pairs` | `{pairs:[…]}` — an agent sees its own, a person or the terminal sees all (terminal pairs stay listed for an hour; `cleanup:{done, saga, grants, leases}` says whether the revocation cleanup finished) |
| POST | `/api/pairs/{pair_id}/handoff` | The driver offers (`state: handoff_pending`, 2 minutes). A person who is not the driver swaps at once (human override). 403 `not_driver`, 409 `bad_state` |
| POST | `/api/pairs/{pair_id}/handoff/accept` | The navigator accepts: roles and grants swap in one transaction, `generation` +1. 403 `not_navigator`, 409 `no_offer` (none, or expired) / `stale_offer` |
| DELETE | `/api/pairs/{pair_id}` | A member ends it (`ended`); a person who is not a member revokes it (`revoked`). Runs the revocation saga; `{ok, pair, cleanup:{done, saga, grants, leases}}`. Idempotent (`already`) |

**Approval** goes through the shared inbox: `GET /api/authz/approvals` lists an item with `kind:"pair"`, `id:"pq-…"` and a `pair` object —
`phrases:{initiator, joiner}`, `bundle:{sessions, dirs, leases, summary}`, `roles:{initiator, joiner}:{name, kind, role}`,
`presets:{driver, navigator}`, `elevatedItems:[{id, label, reasons}]`, `needsReauth`. `POST /api/authz/approvals/{id}/decision`
(browser session only) takes `{decision:"allow"\|"deny"\|"later", elevated?:[ticked items], phrase?}` — `choice`/`scopes`/`ttl` are 400
`choice_unsupported`. Ticks must be a subset of the request (400 `wider_than_requested`) and need an elevated session (403 `elevation_required`);
a wrong `phrase` is 400 `phrase_mismatch` (3rd miss: 409 `phrase_mismatch_locked`, the request is rejected); same decision again is
`replayed:true`, a different one 409 `already_decided`. Events on `/ws-workspace`: `authz_request`/`authz_resolved`/`authz_revoked` with `kind:"pair"`.

## Browser broker

Agents open **isolated browser tabs** (a fresh profile, never the user's Chrome) and drive them through the server. **Without the `browser` token in
`VT_AUTHZ_ENFORCE` every route below answers `404 {"detail":"Not Found"}`, exactly like a missing route**, and nothing else changes. Callers: an agent or
the terminal's `fsh` over the unix socket, a logged-in browser (people), or another Mac's relay (only if a grant names the `browser` relay group;
`eval`, cookies, storage and network are refused over a relay). Hooks and service daemons are 403 `request_not_allowed`. Rules, URL policy, redaction,
limits and failure behavior: `docs/ref/auth.md` «Browser broker». Errors are `{error, reason, …}`; a missing permission is 403 `forbidden` with
`need:{resource, scopes, ops}`.

| Method | Path | Notes |
|---|---|---|
| GET | `/api/browser/adapters` | A person or the terminal, or an agent holding `browser` (ops ∋ read). `{enabled, consented, configError, consentText, adapters:[{name, profile, available, reason, enabled, ops, intercepts}]}`. Names: `playwright`, `cdp` (real), and four local CLI adapters that are placeholders (`available:false, reason:"not_implemented"`). An adapter that declares `profile:"user"` is shown unavailable (`profile_user_unsupported`) |
| POST | `/api/browser/adapters/{name}/enable` | **A person or the terminal only** (agents, peers and relays are 403). JSON `{enabled?: bool (default true), consent?: bool}`. The first time anything is turned on, `consent:true` (a real boolean) is required — else 409 `consent_required` + `consentText`. 409 `adapter_unavailable` (+`adapterReason`), 501 `unsupported_profile`, 404 for an unknown name, 503 `audit_unavailable` (the change is not made without its audit line) |
| POST | `/api/browser/tabs` | Open an isolated tab. JSON `{url?, adapter?, profile?, attach?}`. Needs `browser` (ops ∋ open, and navigate when `url` is given). `201 {ok, tab, navigate?}`. 403 `forbidden`/`url_blocked`, 409 `adapter_disabled`/`no_adapter_enabled`/`adapter_unavailable`, 429 `too_many_tabs` (4 per owner, 12 in all), 503 `adapter_down`. **`profile:"user"` → 501 `unsupported_profile`; `attach` (a tab the broker did not open) needs `browser.sensitive` ops ∋ attach and then is still 501** — connecting to the user's own browser is not implemented |
| GET | `/api/browser/tabs` | An agent sees its own tabs, a person or the terminal sees all: `{tabs:[{id, adapter, state: open\|orphaned\|released, owner, ownerName, pair, humanTaken, released, orphanReason, created, lastUsed, hostGen}]}`. | POST | `/api/browser/tabs/{tab_id}/navigate` | JSON `{url}`. `browser` ops ∋ navigate, 30 per minute per tab. Every redirect hop, subframe and later load is checked by the URL policy; 403 `url_blocked` (+`urlReason`) and the tab is put back on `about:blank` if something slipped through |
| POST | `/api/browser/tabs/{tab_id}/snapshot` | `{url, title, text, elements:[{ref:"e1", role, name, …}]}` (`browser` ops ∋ read). `ref`s are the only way to point at an element and die on navigation |

| POST | `/api/browser/tabs/{tab_id}/click` | JSON `{ref}` (`browser` ops ∋ input). 400 `unknown_ref`; 403 `url_blocked` if the click opened a forbidden address |
| POST | `/api/browser/tabs/{tab_id}/type` | JSON `{ref, text (≤10000), submit?}` (input) |
| POST | `/api/browser/tabs/{tab_id}/eval` | JSON `{script (≤20000)}` → `{result, truncated}` (≤64 KB). **Needs `browser.js`** (nobody has it by default, not even a logged-in person), 10 per minute per tab. Never over a relay |
| POST | `/api/browser/tabs/{tab_id}/cookies` | `browser.sensitive` ops ∋ cookies. Names, domains, paths and flags only. `{values:true}` additionally needs the grant condition `values` (else 403 `forbidden`, `why:"cond_values"`). Never over a relay |
| POST | `/api/browser/tabs/{tab_id}/storage` | Same for local/session storage (key names only unless `values`) |
| POST | `/api/browser/tabs/{tab_id}/network` | `browser.sensitive` ops ∋ network. `Cookie`, `Set-Cookie`, `Authorization`, `Proxy-Authorization` header values and bodies over 64 KB are always `[redacted]` |

Other statuses: 403 `forbidden` with `why:"not_owner"` (the tab belongs to someone else; only a grant naming that tab, or the same pair, works), 404 `not_found`,
409 `tab_not_open` (ownership released), 413 `too_large`, 429 `rate_limited` (+`limit`: `general`/`navigate`/`js`), **503 `tab_orphaned`** (adapter down, host
restarted or lease lost — every operation except close is refused; ownership is kept), 503 `adapter_down`, 503 `tabs_unreadable`, 503 `authz_unavailable`,
503 `audit_unavailable` (scripts and sensitive reads are not run without their audit line).

## Folder leases (`/api/leases`)

A lease marks a path (or glob) as «in use by this session». The endpoints exist whatever `VT_AUTHZ_ENFORCE` says; only with the `lease`
token does FarShell **refuse** the writes it performs itself on a leased path (below). Without it leases are advisory. Rules, limits and
the same-user caveat: `docs/ref/auth.md` «Folder leases and revocation cleanup». Callers: an agent or the terminal's `fsh` over the unix
socket, or a logged-in browser; a hook, a service daemon or a peer is 403 `request_not_allowed`, an unverifiable token caller 403
`identity_unverified`. Not on the relay allowlist. Errors are `{error, reason, …}`.

| Method | Path | Notes |
|---|---|---|
| POST | `/api/leases` | `{glob, mode?:"write"\|"read", exclusive?, ttl?, reason?}` (`path` is accepted for `glob`; `ttl` seconds, default 1800, max 28800). `201 {ok, lease}`. The caller needs `fs.write` (ops `write`) for a write lease, `fs.read` for a read lease on that path (403 `forbidden` with `need:{resource, scopes}`; humans have both). 400 `bad_glob`/`bad_mode`/`bad_ttl`/`ttl_too_long`, 403 `outside_roots` (outside `VT_BROWSE_ROOTS`, deny list, hidden-state folders), **409 `lease_conflict`** `{holder:<nickname>, expires, conflicts:[{holder, expires, mode, exclusive, glob}]}`, 429 `rate_limited` (30 changes a minute per caller) / `too_many_leases`, 503 `audit_unavailable`/`authz_unavailable` |
| POST | `/api/leases/{lease_id}/renew` | `{ttl?}` → `{ok, lease, ...}` with `lease.capped:true` when it hit `created + 8 h`. Holder (or a person) only, else 404; an inherited lease is 409 `derived_lease` |
| DELETE | `/api/leases/{lease_id}` | Holder or a person; releases inherited leases with it. `{ok, id, released}` |
| GET | `/api/leases` | `{leases:[{id, holder, glob, mode, exclusive, reason, created, expires, remaining, maxExpires, derivedFrom, delegation, approvedVia, ttl}], enforced}` — an agent sees its own, a person or the terminal sees all. `holder` is a nickname, never an id |
| POST | `/api/leases/check` | Pure query for the commit guard: `{paths:[absolute…], holder?}` (≤ 5000; `paths` that is not a list of path strings is 400 `bad_paths`, more than 5000 is 413 `too_many_paths`) → `{ok, checked, conflicts:[{path, holder, expires, mode, exclusive, glob, lease}], enforced}`. An agent is checked as itself (`holder` ignored); the terminal may pass a principal id; without one every write lease counts. Changes nothing |
| GET | `/api/authz/leases` | **Browser session only.** All leases, same shape. |
| DELETE | `/api/authz/leases/{lease_id}` | **Browser session only.** Admin revoke (derived leases go with it). `200 {ok, id, released}`, 404 |

**Enforcement (`VT_AUTHZ_ENFORCE=lease`, off by default).** A write that a caller *other than a person and other than the holder (or its
delegation lineage)* makes through `POST /api/git/stage|unstage|commit`, `POST /api/upload?session_id=…`, `POST /api/files/{id}/insert`, a
peer's `POST /api/peer/file` with a session, or `POST /api/delegations` (working folder) is answered **403 `lease_conflict`**
`{error, reason, holder, expires, op, paths, conflicts[]}` when another holder's write (or exclusive) lease covers a target path (503
`lease_unavailable` if the lease store is unreadable). Targets: the repository paths for git (all staged files for a commit), the session's
working folder for the upload/insert/drop routes. Persons are never refused: an overlapping write adds a `lease.override` audit line and a
`lease_notice` event. With the flag off none of these routes behaves differently. The same flag makes grant revoke, panic and host
`deny-*` run the revocation cleanup saga («Folder leases and revocation cleanup»); a spawn with a worktree issues the child an exclusive
write lease on the new path, a same-folder child shares the parent's.

No other header from the peer reaches the browser. Path-based file writes and downloads are not relayed (local only). Pre-checks the same allowlist (403). Peer unreachable → 502 `peer_unreachable`; peer without relay routes → 501 `peer_outdated` |
| WS | `/ws/hosts/{host_id}/relay/{path}` | Same, for WebSockets. The inner route's close codes pass through (4001/4004 keep their meaning); the peer's 4401 becomes 4001 |

With `VT_AUTHZ_ENFORCE=peer` the routes in this table that act on another Mac (the list, every `{host_id}` route including the relay, and both WebSocket proxies) require the caller to hold the scope on `host:<id>`: a person logged in through the browser (and an open server without any password) does; `fsh` over the unix socket only for the list and ping; an agent or the machine token does not (403 `host_access_denied`, WebSocket close 4003). Details: [`docs/ref/auth.md`](./docs/ref/auth.md).

## Update (check and automatic update)

Implemented in `server/update_check.py` and `server/routes/update.py`; behavior and threat model in [`docs/ref/dev.md`](./docs/ref/dev.md) «Update check and automatic update». None of these routes is in the host relay allowlist or the unix-socket allowlist: an agent, a peer, the machine token or a relayed call is refused (`403 human_session_required`).

| Method | Path | Description |
|--------|------|------|
| GET | `/api/update/status` | **Browser login session only.** The last check from `$VT_STATE_DIR/update-status.json` plus the server settings: `{checked_at, channel, current, latest, latest_tag, available, applicable, signature_ok, signer, error, blocked, attempts:{version,count}, auto:{reason,first_seen,…}, last_apply:{result:"running"\|"ok"\|"failed", at, from, to, reason, rolled_back}, settings:{check, auto, auto_hour}, check_enabled, env_off, in_progress}`. `current` is re-read from `VERSION` on every call, so it is right right after an update. `blocked` is why this install cannot take the update (`no_trusted_key`, `dirty`, `devmode`, `channel_unset`); `auto.reason` is why an automatic update did not run yet (`waiting_window`, `busy_terminal_input`, `busy_agent_busy`, `gave_up`, `stalled`, `applying`, or a policy code such as `channel`, `major`, `dirty`, `branch`, `no_trusted_key`, `signature`). `/ws-workspace` also carries two update events: `{"type":"update_status","kind":"checked"\|"settings"\|"applying"\|"failed"\|"reason"}` (re-read the status) and `{"type":"update_restarting","version":"X.Y.Z"}` (the server is about to restart on the new version; the connection returns by itself, tmux sessions are kept).

## Native subagent transcripts

Native children are read-only and distinct from delegated tmux sessions. The existing
agent status entry optionally includes `subagents: {parent_id, items, limited}`.
Items contain only `id`, `cli`, `type`, `label`, `state`, `started_at`, `ended_at`,
`tool`, `tool_count`, `last_message` (500 characters), and `stale`. States are
`working`, `idle`, `done`, `failed`; Codex turn completion is `idle`, not final completion.

| Method | Endpoint | Behavior |
|---|---|---|
| GET | `/api/agents/{tmux_name}/subagents/{agent_id}/transcript` | Authenticated; host-switch relay group `agents`. Optional `cursor` is an opaque, versioned file-generation/byte-offset token (maximum 256 characters). Returns `{items, next_cursor, reset, truncated, pending, last_message, label, state, parent_id}` with `Cache-Control: no-store`. Each item has stable `id`, `kind` (`user`, `assistant`, `tool_call`, `tool_result`), `text` (2000 characters), and optional `tool`. Reads at most 1MiB/200 items; incomplete final lines are retried. Missing file is 200 with `pending:true`. 400 `bad_cursor`, 403 `transcript_denied`, 404 `subagent_not_found`, 422 `unsupported_transcript`. No client-supplied file paths, reasoning blocks, shared-session or MCP access. |

`reset` replaces the viewer's previous generation; `truncated` reports omitted data.
The final hook message is provided separately (at most 2000 characters) to cover delayed
transcript writes. The client removes its temporary answer once the recorded answer arrives.
